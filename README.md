# ComfyUI-QG-tools

一个 ComfyUI 自定义节点包，目前包含三十八个节点：**LoRA 加载器**、**模型加载器（三合一）**、
**图像裁剪 + 旋转 + 补边**、**工作流说明卡**、**工作流开关**、**运行计时器**、**文本**、
**加载文档**、**Google 翻译**、**任意切换**、**展示任意**、**是否判断**、**存在判断**、
**路由阻断**、**字符串切换**、**布尔开关**、
**数值**、**数值滑条**、**数学运算**、**颜色校正**、**颜色匹配**、**图像缩放**、
**图像或 Latent 尺寸**、**种子**、**图像水印**、**文字叠加图像**、**宫格图像拼接**、
**图像对比**、**导出图像**、**遮罩上色**、**遮罩拼接**、**文本合并**、**文本替换**、**文本按分隔符分割**、
**尺寸选择器**、**空 Latent 分辨率**、**画布标签**、**Markdown 便签**。

> 哪些是**本插件原创**、哪些**搬自别的插件**（连上游节点名和许可证）：见下方
> [节点来源](#节点来源原创--搬运) 一节，每个节点章节标题下也单独标了一行。

**Image Crop + Rotate + Pad —— 在节点上直接把画面摆正、裁好、补出画布**

- **看得见地编辑** —— 节点上就是一块编辑面板：拖动画面旋转、拖角裁切、拖边补边，不用来回改参数
- **补出来的地方自动进遮罩** —— 新补的边、旋转留下的角、原图里透明的地方都算「待生成区域」，一路 `mask` 输出
- **附带缝合器** —— `stitcher` 输出把生成结果贴回原图，接下游的缝合节点即可
- **能出规则尺寸** —— 「Divisible by」让输出的长宽能被 8/16/32 整除，模型和 VAE 都开心

**LoRA Loader —— 把整摞 LoRA 收进一个节点里管**

- **一个节点管整摞 LoRA** —— 列表式的行编辑器，每行能搜文件、拖着调强度、随时开关、拖动排序
- **触发词自动汇总** —— 所有启用行的触发词去重后拼成一路字符串输出，直接接进提示词
- **整摞存成模板** —— 常用的 LoRA 组合存下来，在任何同类节点上一键套用
- **吸收模型链上的 LoRA** —— 把串在模型链上下游的其它 LoRA 加载器全部并进来，原节点自动旁通，**出图结果不变**

**模型加载器 —— 三合一：扩散模型 + CLIP + VAE 一次选完**

- 一个节点顶掉「UNET Loader + Load CLIP + Load VAE」三个节点，输出标准 `MODEL` / `CLIP` / `VAE`
- 下拉列表从本机现读，不绑模型家族；节点上只显示短文件名，不会把画布撑宽

**Workflow Note —— 让别人打开你的工作流就知道怎么用**

- 卡片式说明：大标题 + Markdown 正文 + 作者 + 链接，直接画在节点上
- 列出需要的模型和依赖的节点包，**自动和本机安装对照**，每行标出「✓ 已安装 / 缺失」，并给下载按钮
- 一键「从当前工作流检测」，把图里用到的所有自定义节点包列出来

**Workflow Switches —— 一张卡片集中开关工作流**

- 选中若干节点 → 建一个开关，一键旁通/恢复这一整块（比如「放大 + 保存」这套）
- 也能当参数预设用：为「开」和「关」各存一套选中节点的设置值，一键切换
- 折叠后只剩标签和开关，不占画布

**Run Timer —— 这次跑图花了多久，直接写在画布上**

- 整轮队列的秒表：开始跑就走字，跑完停住总时长
- 右键看最近几次的记录，改完设置好和上一次对比
- 时间跟着工作流一起保存，别人打开你的图就知道作者那次跑了多久

**Text —— 画布上的一块随手文本框**

- 手动敲的字，整段作为一路字符串输出，接给任何下游文本输入
- 纯 Python 节点，零依赖、不加载模型

**加载文档 —— 把 Markdown 文件读成一路文本**

- 下拉里选一个文档（.md / .markdown / .txt 都行），节点上直接预览内容，可以切「渲染视图 / 纯文本视图」、放大看、一键复制
- 输出 STRING，接提示词框、CLIP Text Encode、说明卡都行
- 纯文本模式会剥掉 `#`、`*`、表格线这些标记，读起来像一句提示词；原样模式按文件原封不动输出
- 文件放在 ComfyUI 的 `input` 目录（或它旁边的 `md` / `prompts` 目录），也可以直接在 `custom_path` 填绝对路径

**Google 翻译 —— 用 Google 翻译把提示词译成另一种语言**

- 选源语言（auto 自动识别）和目标语言，节点排队运行（按 Run）时就把 `文本` 输出译成目标语言，可直接接 CLIP Text Encode / 提示词框
- 节点上有一个「手动翻译」按钮：开启 `手动翻译` 开关后，按钮会把文本框里的文字就地翻成目标语言（不影响连线的自动翻译）
- 零额外依赖：免费通道用 ComfyUI 核心自带的 `requests` 直连 Google 接口，无需 API key；若设了环境变量 `GOOGLE_TRANSLATION_API_KEY`，则自动改用官方、不限量的 Google Cloud Translation API
- 免费通道 Google 可能对服务端 IP 限流（HTTP 429），限流或网络异常时节点会原样返回原文而不是报错，流水线不会断

- **任意切换 —— 把多个同类型输入并成一路，输出第一个非空、已连接的那个**
- **展示任意 —— 在节点上直接预览任意输入（文本/图像/遮罩/音频/视频），并原样透传**
- **是否判断 —— 布尔分支：为真走「真时」，为假走「假时」，没走的那路不求值**
- **存在判断 —— 有值就真、没值就假，同时把值原样传下去（可选输入没接也照跑）**
- **路由阻断 —— 一条线路的总开关：通过时原样透传，阻断时置空或静默掐断下游**
- **字符串切换 —— 两段提示词写在节点上，拨一下布尔就换，不用再拉两个文本节点**
- **布尔开关 —— 整张节点就是一枚开关：大号「开 / 关」+ 可点的胶囊，扇出到多个下游条件**
- **数值 —— 整数和浮点合一：一张卡片里一个可拖的数字框，类型在标题栏齿轮里切**
- **数值滑条 —— 一根滑条挑一个数：开箱是 0–1 一格 0.1（正好接 LoRA 强度），范围和类型随时改**
- **数学运算 —— 一行表达式算出一个数：`round(a / b * 2, 2)` 写在一张卡片上，a/b/c… 接上游**
- 常用于接「兜底」：有高清模型就走它，没有就走普通版；节点上接几个、槽位自动增减
- 所有输入必须是同一类型（混接 IMAGE 和 LATENT 会报人话错误），全空时也会报错而不是把 `None` 传给下游

**图像缩放 —— 像素或百分比缩放，顺手裁切 / 补边**

- 度量可选「像素」或「百分比」，适配方式三选一：`crop` 铺满后居中裁、`pad` 放下后居中补、`contain` 只缩不裁
- 宽或高填 0 就按另一边等比推算（此时按 `contain` 处理）
- 除了图像，还把结果的**实际宽高**当整数输出，可直接喂给下游的尺寸运算

**图像或 Latent 尺寸 —— 接什么都告诉你宽高**

- 输入是通配类型，IMAGE / MASK / LATENT 都能接；Latent 内部尺寸是除以 8 存的，这里自动乘回 8
- 输出 WIDTH / HEIGHT 两个整数，用来驱动按尺寸分流的节点

**种子 —— 一张卡片管住一个种子**

- 大号数字框里直接改种子；「随机值 / 固定 / Step」一段决定每次排队之后它怎么变（Step 再点一下变 −1）
- 「新种子」抽一枚并固定、「用上次」把上次真跑过的种子填回来，`▾` 里是最近 8 枚跑过的种子
- 底下一行实时显示「上次运行」用的种子——随机值模式下框里已经是下一枚，靠后端回传的值才准
- 老工作流里 `-1 / -2 / -3` 的写法，打开时自动翻译成「随机值 / Step +1 / Step −1」，连线不用重接

**图像水印 —— 贴水印不用再开修图软件**

- 水印可缩放（等比适配 / 按倍数 / 按指定宽高）、可九宫格锚点定位再加像素偏移、可旋转、可调透明程度
- 底图是批次时逐帧贴同一位置；接一张遮罩还能限定哪些区域**不透出**水印
- 修掉了上游透明度失效的 bug：带 alpha 的水印现在真的按透明程度混合，旋转后的边角也正常

**文字叠加图像 —— 把字直接画进图里**

- 选系统字体、字号、颜色（内置六色或自定义 RGB），横排 / 竖排随意，按中心点坐标定位
- 除了画好的图像，还输出**文字形状的遮罩**，方便后续只在有字的区域做处理
- 批次时每一帧都画同样的字（上游只画了第一帧）

**宫格图像拼接 —— 多图拼成一张，节点上直接看**

- 最多 16 张，默认统一成第一张的尺寸、在格内等比居中不裁剪；可设格间间隙与背景色
- `剔除全黑帧` 开关：上游批次节点给未接输入补的黑图占位可以自动丢掉，也能关掉照常拼进去

**遮罩上色 / 遮罩拼接 —— 遮罩的两件小工具**

- 上色：内置六色或自定义 RGB 把遮罩区域涂成纯色，遮罩按 0.5 硬切；单张遮罩会应用到整批
- 拼接：两张遮罩左右 / 上下拼成一张，输出标准 `(1, H, W)`；可开启尺寸统一，把小图拉到与大图同尺寸

**文本替换 —— 一次配好三组替换**

- 最多三组「查找 → 替换」，规则按 1 → 2 → 3 顺序生效
- **默认字面、正则可选**：字面模式下括号、点号、竖线都是普通字符，提示词里的 `(red:1.3)` 能整段删掉；
  切到正则模式可用 `\d+`、`\1` 反向引用，写错直接报错而不是悄悄退化

**文本按分隔符分割 —— 切掉思考块、拆段落**

- 分隔符支持正则；默认 `<think>` 正好用来切掉模型的思考块
- 三路输出：`全部段落`（合集）、`单条切分`（选定那条输入的完整切分）、`指定段落`（第 N 段）

**文本合并 —— 两段文本拼成一段**

- 就是 `文本1 + 分隔符 + 文本2`，原样拼接、不去空格；想要空格或换行就写进分隔符
- 两个文本都是**输入槽**，从上游连过来；分隔符是文本框，直接填（常用来插「，」「 」或换行）
- 只有一路输出（上游声明了第二路「显示帮助」却从不返回值，这里删掉了）

**尺寸选择器 —— 选好比例，直接出空 Latent**

- 预设分辨率 + 比例下拉，可选长边缩放、百万像素档、宽高对齐倍数、帧数（大于 0 即视频模型）
- `比例` 里选 **`采用比例`** —— 用预设**标签**里写的那条比例。预设的像素往往只是近似
  （`2304×1280` 实际是 9:5，标签标的是 `16:9`），选了它才会按真正的 16:9 算；填任意比例
  用下面一行 `自定义比例`（如 `2.39:1`）
- 潜在通道数可选 4 / 16 —— SD1.5 / SDXL 用 4，Flux / SD3 / 视频模型用 16
- `对齐倍数` 留 0 时不额外取整，但**求解比例 / 百万像素 / 长边时仍保证 8 的倍数** ——
  latent 就是按 8 展开的，非 8 的倍数会被悄悄截断（节点报 1215、图只有 1208）
- 修掉了上游两个 bug：通道数写死 16、以及比例填「无」时长边把宽高都套上导致画面变正方形
- 另外自己修了两个：比例会被「向上取整」带偏（16:9 曾算成 7:4）；输出的 Latent 没声明
  8 倍下采样，16 倍模型上出图会翻倍

**空 Latent 分辨率 —— 比例 + 百万像素，一步出 latent**

- 官方的「分辨率选择器」算宽高、「空 Latent」吃宽高，中间得连两根线；这个节点合成一步：
  选比例、给百万像素，直接出空 latent，算好的宽高也一并送出去
- 尺寸算法与官方 `ResolutionSelector` 逐行一致（同样的 sqrt 缩放、同样按 8 的倍数对齐），
  128 组参数实测逐个相同
- 高级里能改对齐倍数（8 / 16 / 32 / 64），给别的模型留口子
- 节点上带一排预览（宽 × 高 + 百万像素），只在 Nodes 2.0 显示 —— 官方在经典画布下同样不画

**图像对比 —— 一张面板对照 A 和 B**

- 三种看图方式：`滑动`（竖线跟着指针，左边 A 右边 B）、`A`、`B`
- 指针离开后自动停在「结果」那张图上——哪一路是结果按连线判断（B 通常是从 A 改出来的那张）
- A 原样从输出送出，所以这个节点可以夹在流程中间，不影响下游

## 安装

**方式一：ComfyUI Manager**

打开 ComfyUI Manager → `Install Custom Nodes` → 搜索 `ComfyUI-QG-Tools`。

> 这条要在插件发布到 [Comfy Registry](https://registry.comfy.org) 之后才可用；
> 还没发布时请用下面的方式二 / 方式三。

**方式二：git clone**

```bash
cd <你的 ComfyUI 目录>/custom_nodes
git clone https://github.com/live1617/ComfyUI-QG-tools
```

**方式三：手动下载**

从 [Releases](https://github.com/live1617/ComfyUI-QG-tools/releases) 下载 zip，
解压到 `custom_nodes/` 下，并确认目录名是 `ComfyUI-QG-tools`。

装完**完整重启 ComfyUI**，控制台应出现：

```

  https://github.com/live1617/ComfyUI-QG-tools
----------------------------------------------------------------------
```

无需 `pip install` 任何东西。三十八个节点都在 `QG-tools` 分类下
（细分：Loaders / Text / Logic / Display / Workflow / Mask / Annotation / Image，

## 节点来源（原创 / 搬运）

38 个节点 = **14 原创**（其中 2 个参考上游思路重写、3 个搬自作者自有旧插件） + **24 搬运**。

口径：**原创看代码是不是自己写的，搬运看是不是整段抄的。**

- **原创** —— 代码自己写：从零实现、参考别家的用法换个思路重写、把自己以前插件里的东西合并进来，三种都算
- **搬运** —— 整段照抄上游代码，只改类名 / 节点 ID / 分类 / 显示名 / 文案，逻辑一行没动

判据很简单：**能不能指出某段代码是从上游原样搬来的** —— 指得出就是搬运，指不出、只是照着别人的思路自己实现，就是原创。参考对象记在 `reference` 里，算原创不等于隐去出处。

逐条对应关系也在 `ORIGINS.json`（机器可读）与 `DEVELOPMENT.md`「抽取来源」一节。

| 节点 ID | 显示名 | 类型 | 上游 / 说明 |
|---|---|---|---|

## Image Crop + Rotate + Pad（裁剪 + 旋转 + 补边）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_ImageCropRotatePad`）· ComfyUI-AusBoss（MIT）「Image Crop + Rotate + Pad 🆎」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


载入一张图，在节点上的编辑面板里做**一次**旋转 / 裁切 / 补边，输出摆正并补好画布的画面，
外加一份标出「该生成哪里」的遮罩。

### 面板怎么用

| 操作 | 效果 |
|---|---|
| 拖画面 | 平移取景框里的画面 |
| 拖角 / 拖边 | 改裁切框 |
| 旋转 | 顺时针旋转（`rotation_degrees`，-180 ~ 180） |
| 拖画布边 | 给某一边补出 `fill_color` 的边（拖出来的就是 padding） |
| 比例 | `crop_aspect_ratio`：锁定裁切框比例，`free` 任意、`source` 跟随原图 |

面板上的改动会直接写回节点参数，所以保存、撤销、API 调用都走 ComfyUI 原生路径。

### 遮罩里有什么

`mask` 白的地方就是「可以让模型画」的地方：

- 补出来的边（padding）；
- 旋转留下的空角；
- 原图里**透过去**的地方（实心度不足 90% 的像素，比如抠图留下的透明边）。

不想让透明区域被当成待生成区域，把 `painted_area` 设成 `keep picture` —— 底下原样保留，
只靠遮罩标记。

### 缝合器

`stitcher` 是一份「怎么把生成结果贴回原图」的说明，接到下游的缝合节点
（AusBoss 的 Stitch Inpaint，或本插件将来搬过来的同类节点）就能自动对齐贴回。
`stitch_blend` 控制贴回的过渡带宽度，`stitch_grow` 控制贴回边界往哪偏。

### 出规则尺寸

`canvas_multiple`（Divisible by）把输出长宽凑成它的整数倍：有补边的那一侧多补几个像素，
没补边的那一侧就裁掉几个像素（两侧各裁一半）。要 8/16/32 整除的模型设这里，`1` = 关闭。
`resize_to_megapixels` + `megapixels` 可以再把结果缩到指定像素预算（与核心
Scale Image to Total Pixels 同语义）。

### 输入 / 输出

14 个必填 + 7 个可选，全部是画布上的参数；画面上常用的一些
（比如旋转、裁切、补边）藏在面板里，不会挤满节点。

| 输出 | 说明 |
|---|---|
| `image` | 变换后的图像 |
| `mask` | 待生成区域（补边 / 旋转空角 / 透明处） |
| `stitcher` | 缝合器（贴回原图用） |
| `original` | 变换前的原图 |
| `width` / `height` | 输出尺寸 |
| `prompt_image` | 给模型看的提示图（带待生成区域的示意） |

### 自定义比例预设（可选）

把插件根目录的 `qg_presets_example.json` 复制成 `qg_presets.json` 再改，
可以往比例下拉里加自己的 `W:H` 条目。文件里有坏条目只会警告一次并跳过，不影响节点注册。

## LoRA Loader

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_LoraLoader`）· ComfyUI-AusBoss（MIT）「LoRA Loader 🆎」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


一个节点管整摞 LoRA：接上 `MODEL`（可选接 `CLIP`），下面排开你要用的所有 LoRA，
输出打好补丁的模型和一行触发词。

### 每一行有什么

| 控件 | 作用 |
|---|---|
| 拖拽手柄 | 按住上下拖动，调整 LoRA 的应用顺序 |
| 开关 | 临时旁通这一行，不必删掉它 |
| 名字 / 选择器 | 点一下打开搜索框挑文件；名字太长会按设置省略 |
| 强度 | 直接在名字上左右拖动就能调，也可以点进数值框；旁边有中心零点强度条 |
| ⓘ | 悬停看预览图、底模、触发词，可顺手查 Civitai |

### 触发词

每个 LoRA 的触发词会自动汇总，**去重**后按 `trigger_separator`（默认 `, `）拼成一路 `triggers`
输出，直接接进提示词。也可以给任意一行**手填自己的触发词**。

有两个刻意的设计：

- 把某行强度调到 **0**，它的触发词**仍然保留** —— 这样对比「用 / 不用这个 LoRA」时只需改权重，提示词不用动。
- 因文件缺失**被跳过**的那一行，不加任何词。

### 整摞存成模板

强度条那一排的 ▤ 按钮可以把当前整摞 LoRA 存成命名模板（存在浏览器本地）。
之后在任何 LoRA Loader 上点开 ▤ 就能一键套用，也能删除。

### 吸收模型链上的 LoRA

齿轮菜单里的 **Absorb chain LoRAs** 会沿本节点的模型链往上下游走，把路上遇到的其它 LoRA 加载器
（包含 rgthree、JPS、Pixaroma 等插件的节点）的 LoRA 全部并进本节点，再把那些节点自动旁通 ——
**出图结果完全不变**，只是整摞 LoRA 集中到了一处管理。

前提是那些节点的 LoRA 不是从连线动态接进来的（例如 rgthree 的 Power Lora Loader 接了外部输入）；
这种情况菜单会提示你先断开。整摞 LoRA 也有行数上限，超出时会提示你先清理几行。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（必填） | `model` | 要打 LoRA 补丁的扩散模型 |
| 输入（必填） | `loras` | 序列化的 LoRA 栈，**由面板托管** —— 改行，不要改这个值 |
| 输入（可选） | `clip` | 不接的话 CLIP 强度会被忽略 |
| 输入（可选） | `trigger_separator` | 触发词之间的分隔符，默认 `, `；在齿轮菜单里改，画布上隐藏 |
| 输入（可选） | `on_missing` | 文件缺失时怎么办，见下 |
| 输出 | `model` | 按行顺序打完所有启用 LoRA 的模型 |
| 输出 | `clip` | 同样处理过的 CLIP |
| 输出 | `triggers` | 所有启用行的触发词，去重后拼成的一行字符串 |

### 文件找不到时

- LoRA **只是被移动过**（还在 `loras` 目录里、换了子文件夹）会在运行时按文件名自动找回来，不用管。
- **真的找不到**时，默认行为是**在采样前直接报错停下**，并在错误信息里点名是哪个文件 ——
  无人值守或脚本化跑图不会静默地少打一个 LoRA。
- 想让它在控制台警告一声然后跳过这一行，把齿轮菜单里的 **Stop on missing LoRA** 关掉即可
  （API 调用时对应 `on_missing: "skip"`）。

### 设置

齿轮按钮里是这个节点类型的偏好设置，存在浏览器本地，跟着你所有工作流走：

| 设置 | 默认 | 作用 |
|---|---|---|
| Default strength | 1.0 | 新加一行时的初始强度 |
| Strength step | 0.05 | 拖动与方向键的步长（按住 Shift 恒为 0.01） |
| Separate model / CLIP strength | 关 | 每行显示两个强度框，分别控制模型和 CLIP |
| Strength bars | 开 | 名字后面的中心零点强度条（青色向右为正，红色向左为负） |
| Trigger word separator | `, ` | 拼接 `triggers` 输出用的分隔符 |
| Stop on missing LoRA | 开 | 关掉后，文件缺失只警告并跳过 |
| Hide file extension | 开 | 名字不显示 `.safetensors` |
| Hide folder names | 开 | 只显示文件名（完整路径仍在提示里） |
| Civitai lookup button | 开 | 信息卡里提供「查 Civitai」按钮 |
| Long names | end | 名字太长时怎么省略；`middle` 会保留结尾的数字 |
| Scrub strength on the name | 开 | 在名字上左右拖动改强度（单击仍然是打开选择器） |
| Preview thumbnails | 开 | 悬停选择器时显示预览图 |

## 模型加载器（三合一加载器）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_TripleLoader`）· 作者自有旧插件 ComfyUI-TripleLoader（MIT）「TripleLoader」，合并进来
<!-- QG-ORIGIN:END -->


把 **扩散模型 + 文本编码器 + VAE** 三个加载器并成一个节点：三样各选一次，
输出标准 `MODEL` / `CLIP` / `VAE` 三路，接到采样器上即可。原本要摆三个节点、来回改三处下拉，
现在一块面板说完。

- **不绑模型家族** —— 底下跑的就是 ComfyUI 三个原生加载器，下拉里的文件列表、权重类型、
  CLIP 类型、加载设备全部在启动时从本机现读，所以 Qwen-Image / Flux / SD 系列都照常能用；
  ComfyUI 升级后选项自动跟着变，不用等插件更新
- **下拉看全路径，节点上看短名** —— 下拉列表里显示完整路径便于区分同名文件；
  选中之后节点上只留文件名，不会把节点撑宽（存的值仍是真实路径，不会被改写）
- **旧工作流不会断** —— 万一某行存的是裸文件名、或路径分隔符不一样，
  运行时会按文件名在 `models/` 下自动找回；真找不到才报错，并点名是哪个文件

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（必填） | `unet_name` | UNET / 扩散模型 |
| 输入（必填） | `weight_dtype` | 权重精度，显存紧张可选 `fp8_e4m3fn` |
| 输入（必填） | `clip_name` | CLIP / 文本编码器 |
| 输入（必填） | `clip_type` | 文本编码器类型（Qwen-Image 选 `qwen_image`） |
| 输入（必填） | `device` | 文本编码器加载设备，选 `cpu` 可省显存（速度变慢） |
| 输入（必填） | `vae_name` | VAE |
| 输出 | `MODEL` / `CLIP` / `VAE` | 三路标准输出，直连采样器 |

## Workflow Note（工作流说明卡）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_WorkflowNote`）· ComfyUI-AusBoss（MIT）「Workflow Note 🆎」，只改类名 / 分类 / 显示名 / 中文文案

给别人（或者在半年后的自己）看的工作流说明书。节点本身不参与出图 —— 没有输入、没有输出、不进提示词，
就是画在画布上的一块卡片。

### 卡片上有什么

| 区块 | 内容 |
|---|---|
| 标题 / 副标题 / 作者 | 卡片抬头，纯文本，点铅笔进入编辑器改 |
| 正文 | Markdown：标题、列表、代码块、链接都支持 |
| Models | 工作流需要的模型：名称、目标文件夹、下载按钮 |
| Node packs | 依赖的自定义节点包：包名、仓库地址、探测用的节点类 |
| Links | 你自己的链接（GitHub、Civitai、教程……） |

### 自动对照本机安装

- **模型行**：点 `↻ check files` 会检查这个文件在对应的 `ComfyUI/models/<文件夹>` 里在不在。
- **节点包行**：按「探测节点类」判断这个包在本机装了没有，装了就标 `✓ 已安装`，没有就标 `缺失` 并给「去获取」按钮。
- 文件在别处（比如放在别的子文件夹）也会指出来，甚至可以提示你哪个 LoRA 加载器的行需要指过去。

### 布局与数据

- 两种布局：**卡片**（默认，完整样式）和 **横幅**（只留一条标题标签）。
- 卡片内容存在节点的一个隐藏 STRING 字段里（JSON），所以保存、撤销、API 格式都走 ComfyUI 原生路径。
- 编辑器里有表单和「原始 JSON」两个页签，复制粘贴卡片给别人就靠 JSON 那页。

| 输出 | —— | 无。节点不会进入执行队列 |

> **来源**：搬运（`QG_WorkflowSwitches`）· ComfyUI-AusBoss（MIT）「Workflow Switches 🆎」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


把一套工作流拆成几块，用一个节点统一切换。适合对比「开不开这一块」的效果、或者做「快速模式 / 全量模式」。
节点自身不运行，也不接任何线，纯粹是画布控制器。

### 建一个开关

1. 在画布上**选中一组节点**（比如放大节点 + 它的保存节点）。
2. 在开关卡片上点 `+ Switch`。
3. 起个名字（比如「高清放大」）。

之后这个开关就是这一组的 关 | 开 按钮。**关** 默认是旁通（bypass）这些节点，图照常往下传；
在设置里可以改成**静音**（mute，下游拿不到输入会停下）。

### 三种不同粒度的开关

| 类型 | 建在哪 | 控制什么 |
|---|---|---|
| 节点开关 | 选中任意若干节点 | 这一组节点的开/关 |
| 分组开关 | 选一个分组 | 整个分组的开/关 |
| 全局开关 | 设置里的分组策略 | 按「不分组 / 每个分组 / 按编号分组」批量生成 |

打开「**一次一个**」后，打开某一行会自动关掉其它行 —— 适合「两个放大模型二选一」这类场景。

### 当参数预设用

开关不只管开关，也能改参数：选中节点后把当前值存成「开」的一套、改成另一套再存成「关」的一套。
之后一键就能把 Steps 设成 8、打开某个 LoRA 行，而不需要真的旁通任何节点。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | —— | 无 |
| 输出 | —— | 无 |

开关状态存在节点自己的属性里，所以随工作流一起保存。

## 加载文档（把 Markdown 读进工作流）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_MDReader`）· 作者自有旧插件 ComfyUI-MD-Reader（MIT）「MarkdownFileReader」，合并进来
<!-- QG-ORIGIN:END -->

把一个 `.md` / `.txt` 文件读成一路 `STRING`：提示词、说明文字、术语表写在文件里，
改文件就行，不用回画布上改文本框。文件放进 ComfyUI 的 `input` 目录就出现在下拉里，
选中之后节点下半部直接把文档显示出来。

- **两种取法** —— `plain` 把 Markdown 记号（`#`、`*`、`-`、`[]()`、表格竖线）剥掉，
  出来就是能直接当提示词的干净文本；`raw` 原样输出，给需要保留格式的场合
- **也能直接给绝对路径** —— 文档不在这几个目录里时，把完整路径填进 `custom_path`，
  填了就用它、盖过下拉的选择
- **文件变了才重跑** —— 按文件修改时间判断，文档没改就沿用缓存，不会让下游白算一遍
- **编码不乱** —— 依次按 UTF-8（带 / 不带 BOM）、GBK、Latin-1 试过去，中文文档不会读成乱码
- **记住上次选的文件** —— 换工作流、重开页面，下拉还停在你看的那一篇

### 节点上的预览

选中文件后，节点里就是一块可滚动的预览区：

- 顶栏四个按钮：**刷新文件列表**（重新扫目录，会提示找到几篇）、**放大查看**（Esc 关闭）、
  **复制当前看到的文本**、**在「渲染后的文档 / 输出的纯文本」之间切换**
- 底部一行状态：字符数 · 文件修改时间 · 当前视图
- 预览区跟着节点高度拉伸 —— 节点拖多高它就显示多少，新建时默认给到 380 × 360

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（必填） | `md_file` | 扫描到的文档列表：`input` 目录 4 层内，以及 ComfyUI 根目录下 `md` / `markdown` / `prompts` / `prompt` 目录 3 层内；认 `.md` `.markdown` `.mdown` `.mdx` `.txt`，最多列 500 个 |
| 输入（必填） | `mode` | `plain` 去记号的纯文本 / `raw` 原文 |
| 输入（可选） | `custom_path` | 绝对路径；填了就用它，盖过下拉 |
| 输出 | `text` | 文档正文（`STRING`，单元素） |

扫描会跳过 `.git`、`__pycache__`、`node_modules`、`venv`、`models`、`custom_nodes`、`web`、
`output` 这类目录，免得把依赖包自带的 README 全列进来。一个文档都没有时，下拉里只留
`<no document>`，节点会提示先放文件再点刷新。

## 任意切换（动态多输入开关）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_AnySwitch`）· 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「GoohaiAnySwitch」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


把任意数量的同类型输入接到节点上，它会输出**第一个非空、已连接的那个**——
接线时连几个，节点上的槽位就自动增减（最少 2 个、最多 16 个），中间的空槽会保留位置，
所以优先级稳定、不会因为中间断开而错位。

- **接兜底** —— 把「高清模型」接在最上面、「普通模型」接在下面；前者有就走前者，没有自动回落到后者
- **类型要一致** —— 所有输入必须是同一类型。混接（比如一个 IMAGE、一个 LATENT）节点会直接报错说清是哪两种类型，而不是把错的数据喂给下游
- **全空会报错** —— 一个输入都没接、或全是空值时，节点报错提示，而不是默默传一个 `None` 让下游不明所以地崩

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（可选） | `any_01 … any_16` | 任意类型的输入，接到哪个就出现哪个；输出第一个非空 |
| 输出 | `any` | 第一个非空、已连接的输入（类型与输入一致，连线时槽位会标成具体类型如「图像」） |

## 是否判断（布尔懒分支）

<!-- QG-ORIGIN:BEGIN -->

## 存在判断（有没有东西过来）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Exists`）
<!-- QG-ORIGIN:END -->


问一句「上游到底有没有东西过来」，顺手把值原样传下去 —— 判定和透传一次办完：

- **判定** —— 有值输出真，没有输出假。输入槽是**可选**的，所以「没接线」本身就是
  一个能判断的状态，而不是执行前的一句报错
- **透传** —— 同一份值从「任意」原样出去，不用把链路拆成两条
- **什么算「没有」** —— 没接线、`None`、空文本 `""`、空列表 / 空字典、**全黑遮罩**、
  **全零潜空间**都算；**`0` 和 `False` 算有** —— 它们是有效数据，不是缺席；
  **全黑图像也算有** —— 那是一张有效的黑图，不是失踪
- **判定口径对齐孤海工具箱的「万能是否存在(GH)」** —— 遮罩上低于 `0.02` 的残差当噪声
  抹平后再判（Qwen Image 2.1 的 RGBA 存盘再读回来会带 1/255~3/255 的残差，预览是全黑的）。
  唯一的区别：**我们只判不改** —— 透传出去的值保持原样，不会真把那些像素抹成 0
- **典型接法** —— 「布尔」接到「是否判断」或「布尔开关」的条件上，「任意」接给那一支
  要用的下游：可选模型没加载时走兜底，而不是让整张图报错

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（可选） | `任意` | 什么都接；不接 / 空值就是这个节点要报告的状态 |
| 输出 | `任意` | 原样透传进来的值（没接时为空） |
| 输出 | `布尔` | 有值真、没有假 |

> 输入是「可选」不是「必填」，这点是设计核心：必填的话 ComfyUI 会在执行前就报
> 「缺少输入」，这个节点永远没有机会输出假。

## 路由阻断（这条线走不走）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_RouteBlocker`）· 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「GoohaiRouteBlocker」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


串在线路中间的一个开关 —— 通过时它等于一根导线，阻断时按你选的方式处理：

- **仅输出空值** —— 值换成空，下游**照常执行**，由它自己处理空值。适合「关掉这一段附加

- **中断后续分支** —— 输出 ComfyUI 原生的执行阻断信号，下游节点**被静默跳过**，等于

不用把线路拆成两股，串在任意位置就行。

| 输入 | `阻断模式` | `仅输出空值` / `中断后续分支` |
| 输入（可选） | `任意` | 要放行或被阻断的值，什么都接；不接时输出就是空 |

## 布尔开关（整张节点就是一枚开关）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_BoolToggle`）
<!-- QG-ORIGIN:END -->


一排布尔条件要一起开、一起关时，一个个去点很烦。这个节点把开关本身放到画布上：整张节点就是
一枚开关 —— 左边一块大字，右边一枚胶囊，点胶囊切换，输出接到多少个下游布尔条件上都行，

- **一眼看出状态** —— 卡片边框在「开」时变成品牌青色，胶囊滑到右边、底色变绿；名字也随状态

- **右键也能切** —— 节点右键菜单里有「打开 / 关掉」，不用瞄准胶囊
- 只有胶囊吃点击，卡片其它地方照常拖动节点；四角留给缩放

| 输出 | `布尔值` | 开关状态，可同时连多个下游；槽名画在卡片上方，不会被卡片压住 |

## 数值（整数 / 浮点合一）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Number`）
<!-- QG-ORIGIN:END -->


一个数字，一张卡片：左边一行小字「值」，右边就是一个数字框 ——
**左右拖动改、单击直接输入、右边上下箭头按步进调**（Shift 细调），
跟包里 LoRA 加载器的强度框是同一件东西。

- **类型在标题栏齿轮里** —— `?` 左边那枚齿轮点开是「数值设置」，整数 / 浮点数二选一。
  二选一占一整行下拉太浪费，也容易被动到，所以收进齿轮里
- **类型决定输出** —— 选整数就输出 `INT`（小数四舍五入掉），选浮点就输出 `FLOAT`；
  输出槽固定是「任意」（`*`），所以两种模式都接得进 `FLOAT` 口（比如 LoRA 强度）
- **步长跟着类型走** —— 整数按 1 走、框里不显示小数点；浮点按 0.1 走、显示两位小数
- **切回整数会取整** —— 卡片里不会有「显示 4、实际 3.7」这种别扭状态
- **值存法跟原生一样** —— 存档、撤销、复制粘贴、API 导出全跟 ComfyUI 自带节点一致
- 一个节点顶两个，不用再纠结拖「整数」还是「浮点数」

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `类型` | 整数 / 浮点数，在标题栏齿轮里切换 |
| 输入 | `值` | 数值本身，拖动 / 单击输入 / 箭头步进 |
| 输出 | `数值` | 类型由「类型」决定，可同时连多个下游 |

> 输出槽声明为「任意」（`*`），因为 ComfyUI 的类型是类级静态的、运行时改不了，真正的
> 类型由实际返回值决定。**别图好看把它改成 `INT` / `FLOAT`** —— 前端会拿它做连线校验，
> 整数模式就再也接不进 `FLOAT` 输入（LoRA 强度），而且 `connect()` 是**静默失败**
> （不报错、也不建线），最难查。

## 数值滑条（范围自己定）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Slider`）
<!-- QG-ORIGIN:END -->


一根滑条挑一个数。跟「数值」的区别只有一个：那边是纯数字框，这边是一根**拖得动**
的滑条，而且**范围自己定**（最小 / 最大），适合「强度 0–1」「步数 20–50」这种有明确
上下界的参数。要精确到某一位，**点右端的数字直接敲**也行。

**开箱就是 0 – 1、一格 0.1、输出小数** —— 也就是 LoRA 强度 / 权重 / 去噪强度最常见
的那个区间，新建节点拖两下就能用。要当计数用，在齿轮里把范围改成 0 – 100、类型改成
整数就行。

卡片就一行，从左到右就是用法：

| 位置 | 内容 | 用途 |
|---|---|---|
| 左 | 滑条轨道 | 唯一的值输入：拖到哪儿值就是多少（一格 = 步长），铺满整行 |
| 中 | 当前值 | 实时读数，小数位跟着步长走（步长 0.25 就显示两位）；**点一下就能直接输入**，回车确认、Esc 取消 |
| 右 | 齿轮 | 点开「滑条设置」：类型、最小、最大、步长都在这儿 |

- **范围在齿轮里** —— 最小 / 最大一次设好就不常动，所以不占卡片；改完滑条立刻跟着
  伸缩，填反了自动对调
- **类型也在齿轮里** —— 整数 / 浮点数二选一，外加**步长**（浮点模式每格多少，默认
  0.1 就是一位小数；0.01 就是两位）
- **整数模式**：滑条一格走 1、读数不带小数、切过去时小数会被四舍五入掉
- **浮点模式**：滑条一格走「步长」，读数的小数位跟着步长走
- **类型决定输出** —— 选整数输出 `INT`、选浮点输出 `FLOAT`；输出槽固定是「任意」，
  所以两种模式都接得进 LoRA 强度那种 `FLOAT` 口（当前是哪种，看右边读数有没有小数位）
- **超范围按两端算** —— 无论是拖滑条还是别的插件塞进来的值，出去时都夹在最小值 /
  最大值之间；把范围收窄时，现有的值也会被夹回来（不会出现「滑条顶在右端、输出
  却是 80」）
- 前后端取整规则一致（`floor(x + 0.5)` ↔ `Math.round`），不会出现「卡片显示 1、输出 0」
- **数值可以直接敲** —— 点右端的读数弹一个输入框（带出当前值），回车确认、Esc 取消；
  打进去的数照样按步长对齐、夹进范围，跟拖出来的没区别
- 轨道**又粗又长**（12px 高 + 20px 滑块），节点开箱 320×58 —— 跟「布尔开关」
  **完全一样大**，两个摆一排是齐平的；读数只占「范围里最大的那个数」那么宽的格子
  （默认 0–1 只有 22px），轨道一直铺到它左缘前 4px（约 237px）
- 画布上这整行是**直接画出来的**（跟布尔开关同一套做法），所以节点高度能压到 58；
  Nodes 2.0 下换成 DOM 卡片，高度由卡片自己撑

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `值` | 当前数值，拖滑条改 |
| 输入 | `最小` | 滑条左端，在齿轮里设 |
| 输入 | `最大` | 滑条右端，在齿轮里设 |
| 输入 | `类型` | 整数 / 浮点数，在齿轮里切 |
| 输入 | `步长` | 浮点模式每格多少（整数模式固定 1），在齿轮里调 |
| 输出 | `数值` | 类型由「类型」决定，可同时连多个下游 |

> 卡片只留了滑条这一个入口：类型、范围、步长都在齿轮菜单里，五个控件本身在画布上
> 收起来了 —— 存档结构不变，读老工作流照样对得上。

## 数学运算（一行表达式）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Math`）
<!-- QG-ORIGIN:END -->


卡片上只有一行：写算式。变量是节点左侧的 `a`、`b`、`c`……
需要「宽按高度算」「百分比」「勾股」这类地方，一行写完就行，不用串三个节点。

```
round(a / b * 2, 2)        # 比例算尺寸，留两位
sqrt(a**2 + b**2)          # 勾股
100 * 2                    # 常数直接写进表达式
a if a > b else b          # 取大的那个
```

- **变量只接上游** —— 左上角默认 `a` / `b` / `c` 三个槽，**接满一个就自己长出下一个**（最多 26 个），
  整数（宽度、高度、帧数）、小数、布尔都能接。**没连线时按 0 算** —— 要写常数直接写进表达式，
  卡片上没有数字框
- **一个结果三种给法** —— `数值`（小数）、`整数`（四舍五入）、`布尔`（非零为真），
  写比较式 `a > b` 时直接把 `布尔` 当条件接到下游
- **函数用法有专门的手册** —— 📖 [数学运算 · 表达式与函数手册](https://github.com/live1617/ComfyUI-QG-tools/blob/main/docs/math.md)：
  每个函数做什么、怎么用、有什么上限，都在里面；节点上的 `?` 是速查版
- **算错会说话** —— 语法错、未知名字、除零都会报出原始算式和原因，不会静默返回 0
- **只解析不执行** —— 表达式走语法树白名单，别人分享的工作流带不进代码

| 类别 | 用法 |
|---|---|
| 运算符 | `+` `-` `*` `/` `//`（整除） `%`（取余） `**`（幂） |
| 比较 / 逻辑 | `==` `!=` `>` `<` `>=` `<=`，`and` `or` `not` |
| 条件 | `a if a > b else b` |
| 常量 | `pi` `e` `tau` |
| 取整 | `round(x, n)` `floor` `ceil` `trunc` `abs` `sign` |
| 数值 | `min` `max` `sum` `pow` `sqrt` `log` `log2` `log10` `exp` `hypot` |
| 三角 | `sin` `cos` `tan` `asin` `acos` `atan` `atan2`，`degrees` / `radians` 换角度 |
| 其他 | `int` `float` `bool` `factorial` `gcd` `lcm` `fmod` `copysign` |

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `表达式` | 算式本身，留空输出 0 |
| 输入（可选） | `a` … `z` | 自动增长的变量槽，默认露出 3 个；整数 / 小数 / 布尔都能接，没连线按 0 |
| 输出 | `数值` / `整数` / `布尔` | 同一个结果的三种形态 |

> `^` 是**按位异或**（Python 语义），幂请写 `**`。全角的 `（ ）＋ × ÷` 和比例写法 `3：4` 会自动归一。
> 每个函数的完整用法和例子见 [docs/math.md](https://github.com/live1617/ComfyUI-QG-tools/blob/main/docs/math.md)。

## 种子（一个数字单独走一根线）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_Seed`）· ComfyUI-AusBoss + rgthree-comfy（MIT）「Seed 🆎 / Seed」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


把种子从采样器里**摘出来单独放**：一根 `INT` 线喂给好几个采样器，改一处全部跟着变；
回头想复现某张图，用的哪枚种子就摆在那儿。

卡片从上到下就是一块：大号数字、下面「随机值 / 固定 / Step」三选一、
最底下「新种子 / 用上次 / 历史」。

- **随机值** —— 每次排队之后重新抽一枚，范围 0 – 2⁵⁰−1（故意不铺到 2⁶⁴，
  再大 JS 的双精度就丢位了）。新建的节点默认就是这一档
- **手输别超过 2⁵³** —— 框里的数在浏览器里是双精度浮点，填更大的值会被悄悄取整；
  上限虽然写的是 2⁶⁴−1，实用区间就在 2⁵³ 以内（随机抽取本来就只到 2⁵⁰）
- **固定** —— 永远用框里这一个
- **Step +1 / −1** —— 每次排队之后加一或减一，扫一段连续区间时用
- **它记得自己真正跑过什么** —— 随机值模式一排队，框里的数字就换成下一枚了，
  所以「刚出的那张用的哪枚」光看框是看不出来的。节点每次运行会把**实际用的值**
  回传：底下一行「上次运行」显示它，「用上次」把它填回框里并切成固定，
  「历史」菜单存最近 8 枚，点一条就填回并固定。历史跟着工作流一起存
- **老工作流照样开** —— v0.8.4 及以前用的是 `-1 / -2 / -3` 哨兵值，
  加载时前端翻译成「模式 + 具体种子」，所以现在种子永远是非负整数
- **高度是钉住的** —— 卡片内容固定，拖角落把它拉高只会在下面多一块空白，所以不让拖

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `种子` | 0 – 18446744073709551615；三档模式决定排队后它怎么变 |
| 输出 | `种子` | 本次实际使用的值，可同时连多个采样器 |

> 搬运自 AusBoss（卡片外观）与 rgthree-comfy（取值与随机逻辑），MIT，保留原出处。

## 颜色校正（六个滑条走完调色）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ColorCorrect`）· 参考 comfyui-art-venture（MIT）「ColorCorrect」的用法，代码自写
<!-- QG-ORIGIN:END -->

六个滑条就是一次完整的调色，不用串一长串节点。它们按摄影调色的顺序依次作用：

**色温 → 明度 → 对比度 → 伽马 → 饱和度 → 色调**

- **温度** —— 冷暖。负值加蓝、正值加黄。三通道增益按 Rec.709 亮度权重做过归一化，
  **调它只变色、不会顺带把画面调亮调暗**
- **色调** —— 整张图的色相旋转，±180 是一整圈。走 HSV 只转 H，饱和度和明度不动，
  **纯红转 120 度就是纯绿**，不会转出一片灰
- **明度 / 对比度** —— 明度是整体乘系数（-100 全黑、+100 亮度翻倍）；
  对比度绕中灰 0.5 拉伸（-100 全片变成 0.5 灰）
- **饱和度** —— 按亮度做混合，**-100 是纯黑白而且亮度不变**，+100 色彩浓度翻倍
- **伽马** —— 只动中间调，两头不动。想提亮暗部又不想冲掉高光时，比直接调明度好用

全程 float 直算：没有 8bit 往返、不逐帧转 PIL、不依赖 OpenCV，所以渐变不出色阶，
整批一次算完。参数回到默认值就跳过那一步 —— 伽马 1.0、其余全 0 时，
输出与输入**逐字节相同**。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` | 批次一次处理完；有 alpha 通道时原样保留 |
| 输入 | `温度` / `色调` / `明度` / `对比度` / `饱和度` / `伽马` | 见上，六个参数互不干扰，任意组合 |
| 输出 | `图像` | 与输入同尺寸、同批次数 |

## 颜色匹配（把一张图的配色搬到另一张）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ColorMatch`）
<!-- QG-ORIGIN:END -->

给它一张目标图和一张参考图，它把参考图的**色调、对比、整体色偏**搬过来，
目标图自己的构图和明暗层次保留。典型用法：把生成图和一张实拍素材的色调对齐、
给一段视频统一成同一个影调、把不同来源的素材剪在一起时统一配色。

**九种方法**（另加一个仅均值），按「换色换到多狠」排列：

| 方法 | 干了什么 | 什么时候用 |
|---|---|---|
| **小波变换** | Haar 小波分解 3 层，只把**最低频子带**的均值 / 方差对齐到参考，细节子带原样保留 | 素材细节多（布料、皮肤、毛发、文字）。换色调但纹理、边缘、噪点全不动 |
| **自适应实例统一化** | AdaIN 的逐通道 `(x-μ)/σ`，**在 sRGB 上**做 | 同源素材、风格化迁移。比莱因哈德更"硬"，不分离亮度与色度 |
| **最大均值差异** | RBF 核下最小化 MMD²(P′,Q)，迭代 60 步求出一组仿射映射 | 参考图的分布是多峰的、不像高斯时，比协方差法更贴 |
| **直方图匹配** | 逐通道按分位数把分布重排成参考的（CDF 匹配） | 要"完全一致"时。均值方差偏斜全对上，也最容易失真 |
| **莱因哈德色彩迁移** | 转到 CIELAB 后逐通道 `(x-μ)/σ` 对齐（Reinhard 2001） | **默认就用它**。亮度和色度解耦，改色不改明暗层次 |
| **多元高斯分布** | LAB 上做 3×3 协方差匹配（Pitié 2007 线性 MKL 的核心：白化再着色） | 修色偏最干净。比逐通道多照顾通道之间的相关性 |
| **直方图匹配-多元高斯分布-直方图匹配** | 三步串联：先把边缘分布拉近，再纠正相关性，最后直方图收尾 | 要边缘分布也对得很准。比单次直方图稳一点 |
| **直方图匹配-最大均值差异-直方图匹配** | 同上，中段换成核均值匹配 | 同上，且参考分布明显非高斯 |
| **Reinhard Lab GPU算法** | 与莱因哈德**同一个数学**，但走整批 4D 张量广播，没有逐帧循环 | 大图、长批次、跑在 GPU 上时更快。结果与莱因哈德逐像素一致 |
| **仅均值** | 只搬平均色，不动对比度 | 最保守。只想换掉整体色偏、不想动观感时 |

几个实现上的取舍：

- **小波只动低频**是有意的 —— 连细节子带一起匹配会把纹理改掉，那就成"重绘"了
- **MMD 求的是仿射映射**，不是逐像素核回归。后者数学上更"正宗"，但 E[Y|X] 的方差
  不可能大于 Y 的方差，实测输出 σ 只剩参考的四成，画面发灰；仿射版一阶 / 二阶统计
  都对得上，图像自身的局部结构也原样保留
- **"直方图匹配-…-直方图匹配"里中间那步的参考不变**，三步都对着同一张参考图，
  不是逐级传递
- **出口不再硬裁** —— 匹配后落到 sRGB 外面的颜色，沿 LCh 的 C 轴缩饱和度（色相与
  明度都不动）。逐通道 clamp 会改掉三原色比例，也就是**改色相**（实测饱和色偏 2–8°），
  这是 W3C 色域映射指南明确要求避免的
- **源侧统计量有下限** —— 目标图本身很平（雾、纯色背景、欠曝暗部）时，σ 会小到
  σ参考/σ源 放大几十倍，噪声和色阶一起炸出来。下限设成归一化 L 的 2%（约 5/255），
  实测同一张近纯色图：无下限偏离 0.12，有下限 0.013
- **遮罩有两个作用，别混** —— 一个是「结果作用在哪」，一个是「统计量从哪取」。
  后者是 Photoshop 匹配颜色的「使用选区计算颜色」：把主体贴进新背景时，背景像素
  不该参与目标侧的均值 / 协方差，否则主体统计被稀释。实测一张主体在左、右半是
  强绿的图，不限定统计时结果被带偏 0.17（归一化 Lab），限定后精确落到参考均值
- **参考图也能单独接遮罩** —— 参考图里有大片无关内容（天空、水面、水印、字幕）时，
  只让选中的区域参与统计。实测参考图左半暖橙、右半冷蓝，全图统计会把结果拉到
  中间（b −0.06），只在左半统计后 b 升到 0.21、贴着左半的真实值
- **细节回填补的是差额，不是原值** —— 直方图匹配把低对比素材拉宽时，颗粒和噪声
  会被一起放大（文献里叫 grain effect，实测高频能量 0.047 → 0.086）；反过来压缩
  时细节又被抹平。按「原图高频 − 结果高频」补，两种方向都能还原，且差额逐通道去
  均值，实测 sRGB 通道均值变化 < 1e-4，只动纹理不动明暗
- **小波变换不吃统计遮罩** —— 它是逐图对齐低频子带，本来就不统计像素分布，
  所以 `遮罩用途` / `参考遮罩` 对它只影响「作用区域」，不影响匹配本身

通用参数：

- **强度** —— 结果与原图的线性混合。0 = 原图，1 = 完全匹配，**0.5 左右通常最自然**
  （留一半原图的味道）。想做「轻微统一影调」就别拉到 1
- **参考取帧** —— 参考图是批次时：`全部合并`（所有帧并成一个样本池统计，最稳）/
  `仅第一帧` / `逐帧对应`（参考帧数不够就循环取）
- **目标统计** —— 目标图是批次时源侧统计怎么算：`逐帧`（每帧各算一套，单张图最贴）/
  `全批统一`（整批合成一套，帧与帧之间的相对差异被保留，**视频不会闪**）。
  视频 / 序列 / AnimateDiff 一律用 `全批统一`；只有一帧时两者等价
- **匹配范围** —— `全部`（明暗和色度都换）/ `仅色度`（保留原图的明暗层次，只换色调）/
  `仅明暗`（保留原图色调，只换对比度与整体亮度）。合成、只想统一影调时很有用
- **遮罩用途** —— `仅结果`（只决定作用区域，统计量仍取全图）/ `也限定目标统计`
  （统计量也只从遮罩内取）。**把主体贴进别的背景时用后者**，背景不会再稀释主体统计
- **细节回填** —— 把高频（纹理、颗粒、边缘锐度）还原到原图的水平。直方图匹配把
  渐变拉成色块、或者把低对比素材的噪点拉炸时调到 0.3–0.6；0 = 不管
- **遮罩羽化** —— 遮罩边缘的高斯羽化宽度（像素），0 = 硬边。接遮罩做局部换色时
  设 8–32，接缝会消失
- **遮罩** —— **作用区域**：白色处应用匹配，黑色处保留原图。做局部换色、
  或者只想统一背景色调时接一张遮罩即可
- **参考遮罩**（可选）—— **参考图上的统计区域**：只有白色处的像素参与统计。
  参考图里有大片无关内容（天空、背景、水印）时接一张，配色不会被它们带偏

参考图**不需要和目标图同尺寸** —— 取的是统计量，不是逐像素对应。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` | 要改的目标图；批次逐帧处理，有 alpha 通道时原样保留 |
| 输入 | `参考图像` | 配色从它身上取，尺寸随意 |
| 输入 | `方法` | 九种 + 仅均值，见上表，默认「莱因哈德色彩迁移」 |
| 输入 | `强度` | 0–1，默认 1.0 |
| 输入 | `参考取帧` | 全部合并 / 仅第一帧 / 逐帧对应，默认全部合并 |
| 输入 | `目标统计` | 逐帧 / 全批统一，默认逐帧 |
| 输入 | `匹配范围` | 全部 / 仅色度 / 仅明暗，默认全部 |
| 输入 | `遮罩羽化` | 0–256 像素，默认 0（硬边） |
| 输入 | `遮罩用途` | 仅结果 / 也限定目标统计，默认仅结果 |
| 输入 | `细节回填` | 0–1，默认 0（不补） |
| 输入 | `遮罩`（可选） | 作用区域，不接就是全图 |
| 输入 | `参考遮罩`（可选） | 参考图上的统计区域，不接就是整张参考图 |
| 输出 | `图像` | 与目标图同尺寸、同批次数 |

全程 float 直算，LAB 走 sRGB → 线性 → XYZ → Lab（D65），出界颜色缩 chroma 后再
clamp 回 `[0,1]`，中间不做 8bit 往返，所以渐变不出色阶。小波用正交归一化 Haar，
正逆变换往返误差在 `1e-7` 量级。

## 尺寸选择器

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_SizeSelector`）· ComfyUI_Muye（MIT）「MuyeSizeSelector」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


选好比例，节点直接给出空 Latent 和实际宽高。

- **预设 + 自定义** —— 预设列表覆盖常见比例；也可以在 `比例` 里自己填 `16:9`、`2.39:1`、`1 1`
- **长边缩放** —— `长边` 填 0 用预设原始尺寸，填 N 就把长边缩到 N 并保持比例
- **百万像素** —— `百万像素` 填 `1.0` / `2.0` 就按面积定尺寸，形状仍由比例决定
- **潜在通道数** —— 4 给 SD1.5 / SDXL，16 给 Flux / SD3 / 视频模型（**上游写死 16，这里是可选的**）
- **帧数与对齐** —— `帧数` 大于 0 即视频模型；`对齐倍数` 把宽高贴到 8/16/32 的倍数上
- **比例不漂移** —— 比例和对齐倍数同时生效时按 `w = rx·k`、`h = ry·k` 求解，两个方向
  同时落在网格上、比例仍然精确；上游是「先改比例、再各自向上取整」，会漂（16:9 在 32 下
  曾被算成 1344×768 = 7:4）
- **自动适配模型的下采样倍数** —— 输出的 Latent 会声明「按 8 倍下采样做的」，16 倍的模型
  （Qwen Image 2.x、Flux 2 Klein）由采样器自己换算；缺了这个声明，出图会正好是设定值的两倍

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `预设尺寸` / `批次大小` | 起手尺寸与批大小 |
| 输入 | `长边` / `比例` / `帧数` / `对齐倍数` / `潜在通道数` | 尺寸微调 |
| 输入（可选） | `宽（覆盖）` / `高（覆盖）` | 接任意数值，大于 0 就优先用它 |
| 输入（可选） | `百万像素` | 0 = 不用；非 0 就按这个面积定尺寸 |
| 输出 | `Latent` / `宽` / `高` / `帧数` | 空潜在张量 + 实际使用的数值 |

## 空 Latent 分辨率（比例 + 百万像素一步出 latent）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_EmptyLatentResolution`）· 作者自有旧插件 ComfyUI-EmptyLatentResolution（MIT）「EmptyLatentResolution」，合并进来
<!-- QG-ORIGIN:END -->

官方的「分辨率选择器」算宽高、官方的「空 Latent」吃宽高，中间得连两根线。这个节点把两步合成一步：
选比例、给百万像素，直接出空 Latent，同时把算好的宽高也送出去。

- **省掉两根线** —— 宽高在节点内部算完就用了，`width` / `height` 同时作为整数输出，
  下游要拿尺寸的地方不用再挂一个测量节点
- **八种比例，写的是摄影叫法** —— `1:1` / `3:2` / `2:3` / `4:3` / `3:4` / `16:9` / `9:16` / `21:9`，
  下拉里标成 Square / Portrait Photo / Widescreen 这些，带 Portrait 的是竖图
- **按面积定尺寸** —— `百万像素` 填 `1.0` / `2.0` 就按总像素算，形状仍由比例决定：
  1.0 MP 在 1:1 下约 1024×1024，2.0 MP 在 3:4 下是 1256×1672
- **对齐倍数可调** —— `对齐倍数` 默认 8（和 latent 的 8 倍下采样对齐），16 / 32 / 64 给新一代模型用；
  宽高先向倍数取整再对齐，不会出现半格
- **和官方算出来的一样** —— 尺寸算法与官方 `ResolutionSelector` 逐行一致（同样的 `sqrt` 缩放、
  同样的 multiple 取整），8 种比例 × 4 档百万像素 × 4 档倍数的 **128 组参数实测逐个相同**；
  latent 结构也与官方 `EmptyLatentImage` 一致（4 通道、同样的 `intermediate_device` /
  `intermediate_dtype`、同样带 `downscale_ratio_spacial=8`）—— 所以把原来那两个节点换成这一个，
  出图尺寸不会变
- **节点上直接看得到结果** —— 自带分辨率预览框，拖比例或百万像素时实时画出得到的形状，
  不用先跑一遍才知道算出多少

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `宽高比`（`aspect_ratio`） | 八种预设比例，决定形状 |
| 输入 | `百万像素`（`megapixels`） | 目标总像素（百万），决定大小 |
| 输入 | `批量大小`（`batch_size`） | 一次出几张空 latent |
| 输入（高级） | `对齐倍数`（`multiple`） | 宽高向这个倍数取整，默认 8 |
| 输入（可选） | `分辨率预览`（`preview`） | 预览控件，读上面三个控件，不参与提交 |
| 输出 | `Latent` / `宽` / `高` | 空潜在张量 + 最终像素宽高 |

## 图像缩放（像素或百分比，crop / pad / contain）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_ImageResize`）· rgthree-comfy（MIT）「RgthreeImageResize」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


给一个目标尺寸把图缩过去，**顺手把实际宽高当整数输出**，下游要算尺寸的地方
不用再接一个测量节点。

- **两种度量** —— `pixels` 填绝对像素；`percentage` 填相对原图的百分比
- **宽或高填 0 = 由另一边按比例推算** —— 只给一边就行，这时强制按 `contain` 走
- **三种贴合方式** —— `crop` 放大铺满再居中裁掉多余（输出恰为目标尺寸）/
  `pad` 缩到装得下再居中补黑边（输出恰为目标尺寸）/ `contain` 缩到装得下就返回
  （某一侧可能小于目标，**不裁不补**）
- **原尺寸直通** —— 目标宽高与原图一致、或两个都填 0 时，图原样返回，不重采样，
  所以「尺寸算下来没变」这条链上不会白丢一次画质
- **重采样用的就是 ComfyUI 自己那套** —— 下拉列表直接取原生 `ImageScale` 的方法表，
  装了什么插件扩展的算法这里也都会有

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` | 要缩放的图像 |
| 输入 | `度量方式` | pixels（像素）/ percentage（百分比） |
| 输入 | `宽` / `高` | 目标宽高；填 0 表示由另一边推算 |
| 输入 | `适配方式` | crop / pad / contain |
| 输入 | `缩放算法` | 与原生 ImageScale 同一份列表 |
| 输出 | `图像` / `宽` / `高` | 缩放结果 + 实际宽高（整数） |

> 搬运自 rgthree-comfy（`RgthreeImageResize`），MIT，保留原出处。

## 图像或 Latent 尺寸（一个入口读宽高）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_ImageOrLatentSize`）· rgthree-comfy（MIT）「Image or Latent Size」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


接什么都行 —— 图像、遮罩、Latent，节点只回 `宽` / `高` 两个整数。

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（可选） | `输入` | 图像 / 遮罩 / Latent 都收 |
| 输出 | `宽` / `高` | 宽高，Latent 已乘回 8 倍 |

> 搬运自 rgthree-comfy（`Image or Latent Size`），MIT，保留原出处。
>
> 一个上游带来的边界：遮罩和图像是靠张量维度区分的，所以**批大小为 1、高度正好
> 1 像素**的图像会被当成遮罩读（宽高对调）。实际几乎不会遇到，行为与上游一致，
> 没有改。

## 导出图像（JPEG / PNG / WEBP，画质就在保存这一步）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ExportImage`）
<!-- QG-ORIGIN:END -->


原生 `SaveImage` 只会写 PNG。社区的 JPG 保存节点大多把 `quality` 写死 90，让你在前面
串一个「压缩」节点 —— 那套**不起作用**：压缩节点交出去的是张量，保存节点会重新编码，
最终画质由保存节点说了算，前面那个旋钮只会白白毁一次图。

所以这里的画质旋钮就放在**真正编码的那一步**：

- **三种格式** —— `JPEG`（有损，最小）/ `PNG`（无损，最大）/ `WEBP`（兼顾，支持透明）
- **`质量` 只对 JPEG / WEBP 生效** —— PNG 是无损的，填了也不参与（压缩级别固定 4，
  与原生 SaveImage 同档）
- **`色度采样` 只对 JPEG 生效** —— `4:4:4` 保留全部彩色细节；`4:2:2` 省约 15% 体积、
  红橙边缘开始发软；`4:2:0` 再省一些
- **透明怎么处理** —— 合成白底 / 合成黑底 / 保留透明（PNG、WEBP 支持）。选 JPEG 时
  「保留透明」会自动退化成白底，不会糊出一圈黑边
- **文件名与原生同形** —— `ComfyUI_00001_.jpg`，五位数递增，扫描目录取最大值 +1，
  所以和原生 `SaveImage` 往同一个文件夹存也**不会互相覆盖**
- **前缀能写模板** —— `%date:yyyyMMdd%` / `%time:HHmmss%` 里可以用
  `yyyy yy MM dd HH hh mm ss`；另有 `%INDEX%`（批次内第几张）和 `%BATCH%`（总数）。
  原生那套 `%width% %height% %year% %month% %day% %hour% %minute% %second% %batch_num%`
  也认，两套可以混着写
- **能存到任意目录** —— 留空写 `output`；填 `auto 图/2026` 就是 output 下的子目录；
  也可填绝对路径、网络共享（`\\NAS\共享\图`）、环境变量（`%USERPROFILE%\Desktop\图`）或
  `~\Desktop\图`。**系统目录、盘符根目录、只写一个盘符（`D:`）会被直接拒绝**，
  相对路径也不许跳出 `output`
- **自定义目录也有预览** —— ComfyUI 的 `/view` 只服务 `output`，所以另存一份最长边
  1600 的缩略图到 `temp` 给节点显示，不为了预览再存一张全图
- **不会被缓存跳过** —— 保存节点每次都真的写盘，不会因为「输入没变」就不存

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` | 图像批次，每张单独存一个文件 |
| 输入 | `格式` | JPEG / PNG / WEBP |
| 输入 | `质量` | 1–100，默认 90（只对 JPEG / WEBP） |
| 输入 | `色度采样` | 4:4:4 / 4:2:2 / 4:2:0（只对 JPEG） |
| 输入 | `透明处理` | 合成白底 / 合成黑底 / 保留透明 |
| 输入 | `文件名前缀` | 前缀 + 日期时间与序号模板 |
| 输入（可选） | `保存路径` | 目标目录，留空 = `output` |
| 输出 | — | 没有输出槽（终点节点） |

> 原创。只借了同类节点「画质旋钮该放在编码那一步」的结论，代码没搬。

## Nodes 2.0（Vue 渲染）

ComfyUI 新版可以把节点渲染成 Vue 组件（设置里的「Nodes 2.0 / Vue 渲染」）。
开启后画布不再调用节点自己的 `onDrawForeground`，所以**把界面画在 canvas 上的节点会整块消失**。
本包把这类节点全部迁到了 DOM，两种渲染模式下表现一致：

- **标注 / 便签**：画布标签、Markdown 便签
- **数值 / 开关**：数值、布尔开关、运行计时
- **图像**：导出图像（含概要行与齿轮）

其余节点（各类加载器、显示任意、文本替换、加载文档、数学运算……）本来就以 DOM 卡片
或原生控件呈现，两种模式下一直在。

几个要点：

- **就地切换，不重载工作流** —— 改设置的那一刻，节点自己从旧容器搬到新外壳，位置、连线、
  选中状态、正在编辑的文字全部保留；撤销栈也不会被清掉。
- **双击进入编辑**（标签 / 便签类）—— Vue 模式下单击被用来拖节点，所以编辑改成双击，
  阈值放宽到 750ms，手慢一点也算。
- **不出双影** —— Vue 模式下 `draw()` 直接短路，画布上不重复画一遍。
- **尺寸按外壳换算** —— Vue 会额外加 30px 标题栏和最小宽度，插件按它算节点尺寸，
  切换瞬间节点不会突然变宽变高。

**中英文都能搜到**：中文靠语言包里的译名，英文靠标题本身。除此之外每个节点还登记了一组
口语叫法（`web/shared/node_aliases.mjs`），页面加载时写进节点定义的 `search_aliases`，
ComfyUI 的搜索框会把它们和标题一起做模糊匹配。

| 想找 | 可以搜 |
|---|---|
| 图像对比 | `compare` / `image compare` / `ab compare` / `diff` / `before after` |
| 图像水印 | `watermark` / `logo` / `stamp` |
| 图像裁剪 + 旋转 + 补边 | `crop` / `rotate` / `pad` / `outpaint` |
| 模型加载器 | `triple loader` / `model loader` / `checkpoint` / `unet clip vae` |
| 尺寸选择器 | `size selector` / `aspect ratio` / `resolution` |
| 遮罩上色 / 拼接 | `mask colorize` / `mask concat` / `merge masks` |

想加词就改 `web/shared/node_aliases.mjs` 里对应节点那一行，刷新页面即可。

**命中别名的节点会往前提一点，但最多 2 个。** 这不是多余的设计：搜索框只取前 64 条，
而 `text` 这类词能命中 480 多个节点，QG 文本原本排第 159 名——等于搜不到。所以扩展会把
「别名里正好有这个词」的 QG 节点提到前面，最多提 2 个，其余保持原位。

搜 `image` 这种上位词时是 `QG 图像缩放`、`QG 图像水印` 排前两位，第 3 个就是原生节点；
搜 `text` 时是 `QG 文本`、`QG 文本按分隔符分割` 排前两位。不想看到这个行为的话，
把 `web/shared/node_aliases.mjs` 末尾那几个上位词（`image` / `mask` / `size` / `model` /
`document` / `workflow` / `text`）删掉即可，节点自己的英文名还会保留。

## 生效与排障

1. 首次安装要**完整重启 ComfyUI**（不是刷新页面）。
2. 之后前端有更新时，浏览器要 `Ctrl+Shift+R` 强刷 —— ComfyUI 只在页面加载时读一次扩展列表。
   （本插件的前端子模块都带版本串，正常情况下普通 F5 也能拿到新代码。）
3. 后端共 16 条路由（LoRA 6 条 + 文档 3 条 + Google 翻译 1 条 + 图像面板的视频预览 4 条 +
   图像对比保存 1 条 + 版本探针 1 条），可用这条命令快速自检：

   ```bash
   curl http://127.0.0.1:8188/qg/pack_version
   curl http://127.0.0.1:8188/qg/lora/list
   ```
