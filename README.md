# ComfyUI-QG-tools

一个 ComfyUI 自定义节点包，目前包含五十七个节点：

| 分类 | 节点 |
|---|---|
| **加载器** | 模型加载器、LoRA 加载器 |
| **画布编辑** | 图像裁剪 + 旋转 + 补边、扩图画板（可视化）、图像对比、加载图像、导出图像、采样预览 |
| **遮罩** | 按遮罩抠图、遮罩混合运算、遮罩分析、遮罩检测、遮罩精修、遮罩裁剪、裁剪恢复、遮罩对齐、遮罩上色、遮罩拼接、重绘裁剪、重绘缝合 |
| **图像** | 图像缩放、图片标准化、添加水印、颜色校正、颜色匹配、宫格图像拼接 |
| **文本** | 提示词行、文本、文本合并、文本替换、文本按分隔符分割、加载文档、Google 翻译 |
| **逻辑** | 任意切换、展示任意、路由阻断、是否判断、存在判断、字符串切换、布尔开关 |
| **数值** | 数值、数值滑条、数学运算、双式数学运算、长短边、种子、尺寸选择器、空 Latent 分辨率、图像或 Latent 尺寸、比例与分辨率、释放显存 |
| **工作流** | 工作流说明卡、工作流开关、运行计时器、注释、设置点、获取点 |

> 上表按**用途**分组，节点菜单里按 `QG-tools` 下的八个子分类（Loaders / Text / Logic /
> Display / Workflow / Mask / Retouch / Image）排列，两者不是一一对应。

> 哪些是**本插件原创**、哪些**搬自别的插件**（连上游节点名和许可证）：见下方
> [节点来源](#节点来源原创--搬运) 一节，每个节点章节标题下也单独标了一行。

**Image Crop + Rotate + Pad —— 在节点上直接把画面摆正、裁好、补出画布**

- **看得见地编辑** —— 节点上就是一块编辑面板：拖动画面旋转、拖角裁切、拖边补边，不用来回改参数
- **补出来的地方自动进遮罩** —— 新补的边、旋转留下的角、原图里透明的地方都算「待生成区域」，一路 `mask` 输出
- **附带缝合器** —— `stitcher` 输出把生成结果贴回原图，接下游的缝合节点即可
- **能出规则尺寸** —— 「Divisible by」让输出的长宽能被 8/16/32 整除，模型和 VAE 都开心

**Outpaint Board —— 把画板往外扩，遮罩跟着长**

- **点哪扩哪** —— 点边框外那侧就吸到鼠标处，点右下角外侧则下和右一起改；拖边框可以连续调
- **扩了能缩** —— 点回的边、拖回的框都算数，扩出去不是一道单向门
- **扩边时画面不跳** —— 缩放钉死，点一下只改画板；想再扩就滚轮缩小，可见范围就是上限
- **像素原样复制** —— 不重采样，输出里原图那一块与输入逐位相同
- **尺寸可控** —— 长边上限只削补边不动图；整除数把画布向上取整，差额补在右下

**LoRA Loader —— 把整摞 LoRA 收进一个节点里管**

- **一次加一批** —— 选择框里每个文件都带勾选框：Ctrl 点逐个勾、Shift 点一段，底部一次加入；已经在栈里的文件自动标灰，不给重复勾
- **自动补 Civitai 封面图** —— 查 Civitai 信息时顺带把第一张图存成预览，之后悬停就能看到；分级可调，**你自己放的图永远不会被覆盖**
- **一个节点管整摞 LoRA** —— 列表式的行编辑器，每行能搜文件、拖着调强度、随时开关、拖动排序
- **触发词自动汇总** —— 所有启用行的触发词去重后拼成一路字符串输出，直接接进提示词
- **整摞存成模板** —— 常用的 LoRA 组合存下来，在任何同类节点上一键套用
- **吸收模型链上的 LoRA** —— 把串在模型链上下游的其它 LoRA 加载器全部并进来，原节点自动旁通，**出图结果不变**

**模型加载器 —— 三合一：扩散模型 + CLIP + VAE 一次选完**

- 一个节点顶掉「UNET Loader + Load CLIP + Load VAE」三个节点，输出标准 `MODEL` / `CLIP` / `VAE`
- 下拉列表从本机现读，不绑模型家族；节点上只显示短文件名，不会把画布撑宽

**Workflow Note —— 让别人打开你的工作流就知道怎么用**

- 卡片式说明：大标题 + Markdown 正文 + 作者 + 链接，直接画在节点上
- 列出需要的模型和依赖的节点包，**自动和本机安装对照**，每行标出「✓ 已安装 / 缺失」，并给下载按钮
- 一键「从当前工作流检测」，把图里用到的所有自定义节点包列出来

**Workflow Switches —— 一张卡片集中开关工作流**

- 选中若干节点 → 建一个开关，一键旁通/恢复这一整块（比如「放大 + 保存」这套）
- 也能当参数预设用：为「开」和「关」各存一套选中节点的设置值，一键切换
- 折叠后只剩标签和开关，不占画布

**Run Timer —— 这次跑图花了多久，直接写在画布上**

- 整轮队列的秒表：开始跑就走字，跑完停住总时长
- 右键看最近几次的记录，改完设置好和上一次对比
- 时间跟着工作流一起保存，别人打开你的图就知道作者那次跑了多久

**Text —— 画布上的一块随手文本框**

- 手动敲的字，整段作为一路字符串输出，接给任何下游文本输入
- 纯 Python 节点，零依赖、不加载模型

**加载文档 —— 把 Markdown 文件读成一路文本**

- 下拉里选一个文档（.md / .markdown / .txt 都行），节点上直接预览内容，可以切「渲染视图 / 纯文本视图」、放大看、一键复制
- 输出 STRING，接提示词框、CLIP Text Encode、说明卡都行
- 纯文本模式会剥掉 `#`、`*`、表格线这些标记，读起来像一句提示词；原样模式按文件原封不动输出
- 文件放在 ComfyUI 的 `input` 目录（或它旁边的 `md` / `prompts` 目录），也可以直接在 `custom_path` 填绝对路径

**Google 翻译 —— 用 Google 翻译把提示词译成另一种语言**

- 选源语言（auto 自动识别）和目标语言，节点排队运行（按 Run）时就把 `文本` 输出译成目标语言，可直接接 CLIP Text Encode / 提示词框
- 节点上有一个「手动翻译」按钮：开启 `手动翻译` 开关后，按钮会把文本框里的文字就地翻成目标语言（不影响连线的自动翻译）
- 零额外依赖：免费通道用 ComfyUI 核心自带的 `requests` 直连 Google 接口，无需 API key；若设了环境变量 `GOOGLE_TRANSLATION_API_KEY`，则自动改用官方、不限量的 Google Cloud Translation API
- 免费通道 Google 可能对服务端 IP 限流（HTTP 429），限流或网络异常时节点会原样返回原文而不是报错，流水线不会断

- **任意切换 —— 把多个同类型输入并成一路，输出第一个非空、已连接的那个**
- **展示任意 —— 在节点上直接预览任意输入（文本/图像/遮罩/音频/视频），并原样透传**
- **是否判断 —— 布尔分支：为真走「真时」，为假走「假时」，没走的那路不求值；只接一路也能跑**
- **存在判断 —— 有值就真、没值就假，同时把值原样传下去（可选输入没接也照跑）**
- **路由阻断 —— 一条线路的总开关：通过时原样透传，阻断时置空或静默掐断下游，且打开后上游根本不求值**
- **字符串切换 —— 两段提示词写在节点上，拨一下布尔就换，不用再拉两个文本节点**
- **布尔开关 —— 整张节点就是一枚开关：大号「开 / 关」+ 可点的胶囊，扇出到多个下游条件**
- **数值 —— 整数和浮点合一：一张卡片里一个可拖的数字框，类型在标题栏齿轮里切**
- **数值滑条 —— 一根滑条挑一个数：开箱是 0–1 一格 0.1（正好接 LoRA 强度），范围和类型随时改**
- **数学运算 —— 一行表达式算出一个数：`round(a / b * 2, 2)` 写在一张卡片上，a/b/c… 接上游**
- 常用于接「兜底」：有高清模型就走它，没有就走普通版；节点上接几个、槽位自动增减
- 所有输入必须是同一类型（混接 IMAGE 和 LATENT 会报人话错误），全空时也会报错而不是把 `None` 传给下游

**图像缩放 —— 像素或百分比缩放，顺手裁切 / 补边**

- 度量可选「像素」或「百分比」，适配方式三选一：`crop` 铺满后居中裁、`pad` 放下后居中补、`contain` 只缩不裁
- 宽或高填 0 就按另一边等比推算（此时按 `contain` 处理）
- 除了图像，还把结果的**实际宽高**当整数输出，可直接喂给下游的尺寸运算

**图像或 Latent 尺寸 —— 接什么都告诉你宽高**

- 输入是通配类型，IMAGE / MASK / LATENT 都能接；Latent 内部尺寸是除以 8 存的，这里自动乘回 8
- 输出 WIDTH / HEIGHT 两个整数，用来驱动按尺寸分流的节点
- **遮罩的各种形状都认** —— `(B,H,W)`、`(B,1,H,W)`、`(H,W)` 都读得对。ComfyUI 的
  `ImageToMask` 和 `LoadImage` 给的都是三维 `(B,H,W)`，这是最常见的一种
- 没接线时宽高都给 0，不报错

> 自写。思路来自 rgthree-comfy 的 `Image or Latent Size`（MIT），10-30 重写：修掉
> 「只认四维张量」——原来接最常见的三维遮罩会得到 0×0，且不给任何提示。

**种子 —— 一张卡片管住一个种子**

- 大号数字框里直接改种子；「随机值 / 固定 / Step」一段决定每次排队之后它怎么变（Step 再点一下变 −1）
- 「新种子」抽一枚并固定、「用上次」把上次真跑过的种子填回来，`▾` 里是最近 8 枚跑过的种子
- 底下一行实时显示「上次运行」用的种子——随机值模式下框里已经是下一枚，靠后端回传的值才准
- 老工作流里 `-1 / -2 / -3` 的写法，打开时自动翻译成「随机值 / Step +1 / Step −1」，连线不用重接

**宫格图像拼接 —— 多图拼成一张，节点上直接看**

- 最多 16 张，默认统一成第一张的尺寸、在格内等比居中不裁剪；可设格间间隙与背景色
- `剔除全黑帧` 开关：上游批次节点给未接输入补的黑图占位可以自动丢掉，也能关掉照常拼进去

**遮罩上色 / 遮罩拼接 —— 遮罩的两件小工具**

- 上色：内置六色或自定义 RGB 把遮罩区域涂成纯色，遮罩按 0.5 硬切；单张遮罩会应用到整批
- 拼接：两张遮罩左右 / 上下拼成一张，输出标准 `(1, H, W)`；可开启尺寸统一，把小图拉到与大图同尺寸

**文本替换 —— 一次配好三组替换**

- 最多三组「查找 → 替换」，规则按 1 → 2 → 3 顺序生效，后一条看得到前一条的产物
- **默认字面、正则可选**：字面模式下括号、点号、竖线都是普通字符，提示词里的 `(red:1.3)` 能整段删掉；
  切到正则模式可用 `\d+`、`\1` 反向引用，写错直接报错而不是悄悄退化
- **查找留空就跳过整组** —— 不是「在每个字之间插替换串」（`str.replace("", x)` 会干这事）
- **正则模式下替换内容是模板** —— `\1` 是第 1 个分组，所以想原样插一个反斜杠得写两次：
  `C:\temp` 会静默变成「C: + 制表符 + emp」，`C:\xyz` 直接报错。要插 Windows 路径又不想
  操心转义，就把那条规则换回字面模式
- 写错时报错会点名**第几条规则**、错在「查找内容」还是「替换内容」

> 自写。思路来自 Comfyroll 的 `CR_TextReplace`（MIT），10-30 重写：输出类型从任意改成
> `STRING`，正则模式替换内容的报错从原始英文改成点名到栏位。

**文本按分隔符分割 —— 切掉思考块、拆段落**

- 分隔符支持正则；默认 `<think>` 正好用来切掉模型的思考块
- 三路输出：`全部段落`（合集）、`单条切分`（选定那条输入的完整切分）、`指定段落`（第 N 段）
- **三个序号各管各的** —— 列表序号设 0 只让「单条切分」空，「指定段落」照旧取它自己那一位
- 空的段落会被丢掉，所以序号数的是**非空段**：文本开头就带分隔符时，不会有空段把序号顶偏
- 正则里用了捕获组的话，分隔符本身会留在结果里（`(,)` 切 `a,b` 得 `a`、`,`、`b`）——
  这是 Python 的 `re.split` 语义，需要连分隔符一起留下时才这么写

> 自写。思路来自 ComfyUI_Muye 的 `TextSplitByDelimiterEnhanced`（MIT），10-30 重写：修掉
> 「列表序号设 0 会把指定段落也清空」，非法正则的报错改成中文并点名分隔符。

**文本合并 —— 两段文本拼成一段**

- 就是 `文本1 + 分隔符 + 文本2`，原样拼接、不去空格；想要空格或换行就写进分隔符
- 两个文本都是**输入槽**，从上游连过来；分隔符是文本框，直接填（常用来插「，」「 」或换行）
- **只接一路也干净** —— 没接的那一路连同分隔符一起省掉。单接一段时结果就是那一段，
  不会尾巴上多一个 `-`（也别指望靠它「补分隔符」）
- **空文本仍算数** —— 接了线但是空字符串照样参与拼接，`空 + "-" + X` 还是 `-X`。
  「没接线」和「接了但是空」是两件事，这一点和别的拼接节点不一样
- 只有一路输出（上游声明了第二路「显示帮助」却从不返回值，这里删掉了）

> 自写。思路来自 Comfyroll 的 `CR_TextConcatenate`（MIT），10-30 重写：修掉
> 「只接一路时会多出孤零零的分隔符」，输出类型从任意改成 `STRING`。

**尺寸选择器 —— 选好比例，直接出空 Latent**

- 预设分辨率 + 比例下拉，可选长边缩放、百万像素档、宽高对齐倍数、帧数（大于 0 即视频模型）
- `比例` 里选 **`采用比例`** —— 用预设**标签**里写的那条比例。预设的像素往往只是近似
  （`2304×1280` 实际是 9:5，标签标的是 `16:9`），选了它才会按真正的 16:9 算；填任意比例
  用下面一行 `自定义比例`（如 `2.39:1`）
- 潜在通道数可选 4 / 16 —— SD1.5 / SDXL 用 4，Flux / SD3 / 视频模型用 16
- `对齐倍数` 留 0 时不额外取整，但**求解比例 / 百万像素 / 长边时仍保证 8 的倍数** ——
  latent 就是按 8 展开的，非 8 的倍数会被悄悄截断（节点报 1215、图只有 1208）
- 修掉了上游两个 bug：通道数写死 16、以及比例填「无」时长边把宽高都套上导致画面变正方形
- 另外自己修了两个：比例会被「向上取整」带偏（16:9 曾算成 7:4）；输出的 Latent 没声明
  8 倍下采样，16 倍模型上出图会翻倍

**空 Latent 分辨率 —— 比例 + 百万像素，一步出 latent**

- 官方的「分辨率选择器」算宽高、「空 Latent」吃宽高，中间得连两根线；这个节点合成一步：
  选比例、给百万像素，直接出空 latent，算好的宽高也一并送出去
- 尺寸算法与官方 `ResolutionSelector` 逐行一致（同样的 sqrt 缩放、同样按 8 的倍数对齐），
  128 组参数实测逐个相同
- 高级里能改对齐倍数（8 / 16 / 32 / 64），给别的模型留口子
- 节点上带一排预览（宽 × 高 + 百万像素），只在 Nodes 2.0 显示 —— 官方在经典画布下同样不画

**图像对比 —— 一张面板对照 A 和 B**

- 三种看图方式：`滑动`（竖线跟着指针，左边 A 右边 B）、`A`、`B`
- 指针离开后自动停在「结果」那张图上——哪一路是结果按连线判断（B 通常是从 A 改出来的那张）
- A 原样从输出送出，所以这个节点可以夹在流程中间，不影响下游

- **当前版本**：v0.9.15（支持 Nodes 2.0 / Vue 渲染）
- **节点**：57 个（完整清单见开头那张按用途分组的表；这里不再重复列一遍 ——
  复制两份清单的结果是两份都会漂）
- **分类**：全部在 `QG-tools` 下，八个子分类
  `Loaders` / `Text` / `Logic` / `Display` / `Workflow` / `Mask` / `Retouch` / `Image`
  （中文界面上显示为 加载器 / 文本 / 逻辑 / 展示 / 工作流 / 遮罩 / 重绘 / 图像）
- **依赖**：无额外 pip 包。只用 ComfyUI 运行期自带的模块（torch / numpy / PIL / PyAV / folder_paths / comfy.*）；
  `scipy`、`pymatting` 用到了才用，缺了有内置回退，不报错。
- **许可证**：[GPL-3.0-or-later](LICENSE)

## 安装

> **版本要求**：ComfyUI **0.3.47 或更新**（`comfy_api.latest` 从这个版本开始有）。更老的版本
> 照样能装、能用，只是 `QG_DisplayAny` 的 VIDEO 预览那条分支不可用（代码里有降级，不会报错）。
> 界面建议配前端 **1.5x+**：Nodes 2.0 下的面板高度跟随依赖它，经典画布不受影响。


**方式一：ComfyUI Manager**

打开 ComfyUI Manager → `Install Custom Nodes` → 搜索 `ComfyUI-QG-Tools`。

> 这条要在插件发布到 [Comfy Registry](https://registry.comfy.org) 之后才可用；
> 还没发布时请用下面的方式二 / 方式三。

**方式二：git clone**

```bash
cd <你的 ComfyUI 目录>/custom_nodes
git clone https://github.com/live1617/ComfyUI-QG-tools
```

**方式三：手动下载**

从 [Releases](https://github.com/live1617/ComfyUI-QG-tools/releases) 下载 zip，
解压到 `custom_nodes/` 下，并确认目录名是 `ComfyUI-QG-tools`。

装完**完整重启 ComfyUI**，控制台应出现：


## 节点来源（原创 / 搬运）

57 个节点 = **51 原创**（其中 27 个参考上游思路重写、16 个搬自作者自有插件） + **6 搬运**。

口径：**原创看代码是不是自己写的，搬运看是不是整段抄的。**

- **原创** —— 代码自己写：从零实现、参考别家的用法换个思路重写、把自己以前插件里的东西合并进来，三种都算
- **搬运** —— 整段照抄上游代码，只改类名 / 节点 ID / 分类 / 显示名 / 文案，逻辑一行没动

判据很简单：**能不能指出某段代码是从上游原样搬来的** —— 指得出就是搬运，指不出、只是照着别人的思路自己实现，就是原创。参考对象记在 `reference` 里，算原创不等于隐去出处。

逐条对应关系也在 `ORIGINS.json`（机器可读）与 `DEVELOPMENT.md`「抽取来源」一节。

## Load Image（加载图像）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_LoadImage`）· 参考 Goohaitools-comfyui（GPL-3.0）「加载图像」的用法，代码自写
<!-- QG-ORIGIN:END -->

官方的 Load Image 有两处让人默默吃亏：透明 PNG 被压成三通道，透明处的**原始颜色**
（多半是黑）会跟着进下游，抠图一合成就是一圈脏边；没有 alpha 的文件则退回一块
**64 × 64 的遮罩**，跟图片尺寸毫无关系。

透明只由一个开关管：

| 保留透明通道 | 图像输出 |
|---|---|
| 关（默认） | 透明处合成白底，跟看图软件看到的一样，三通道 |
| 开 | 原样输出四通道 RGBA |

遮罩输出尺寸恒等于图片，画上的地方为 1、没画的地方为 0，可以直接接局部重绘。
输出只有这两个；宽、高、帧数写在面板图下方，不占输出槽（早先还有个「文件名」槽，
用来给导出节点起名 —— 那件事一个字符串节点就能做，占一根线不值）。

想在一张图上直接看到遮罩范围，打开**输出带色图**：把编辑器里画好的颜色一起带出来 ——
**每一笔保留自己选的颜色**（红一笔、蓝一笔都行），浓度就是编辑器里那根透明度滑条。
默认关 —— 关着 `IMAGE` 是干净的原图。颜色烧在成品 PNG 的 RGB 里，而干净画面是从配对的原图
副本取的，所以怎么画都不会把颜色漏到干净输出上。

| 输入 | 说明 |
|---|---|
| `image` | input 里的图片；上传、拖拽、选择器都落到这里 |
| `保留透明通道` | 关：透明处合成白底，三通道；开：原样四通道 |
| `输出带色图` | 由编辑器顶栏那三段决定（不是面板上的开关了）：彩色叠加带色，另两个只存遮罩 |
| `upload` | 上传按钮，只藏外观不动 widget 顺序 |

面板上只留四样：**文件名 + 上传、图、编辑遮罩、`宽 × 高` + 一颗齿轮**。齿轮里只剩
「保留透明通道」（跟输出格式有关，不属于画遮罩那套）。点面板外面、滚一下画布、按 Esc 都会收起。

**「带不带色」是画的时候在编辑器里定的**（照孤海的做法）：顶栏三段「彩色叠加 / 仅遮罩 / 原图」
决定存出去的成品 —— 只有彩色叠加把颜色烧进 RGB，另两个只存遮罩。**屏幕上除了「原图」那一档，
看到的永远是带色的图**，所以「仅遮罩」不会让你眼前一黑。颜色点哪一颗、浓度拖多少也都在编辑器
底栏里定，保存时连同输出档位一起回写节点。

**遮罩编辑器画的结果默认不会进画面。** 这一点照孤海那支的做法：保存时在 `input/clipspace`
下同时写三个 PNG —— 一份原图副本（留住它自己的 alpha），一份不透明的带色画面（给编辑器
取颜色用），一份把遮罩存进 alpha 通道的成品；读回来时用副本的 alpha 换回成品里的 alpha，所以 `IMAGE` 是画之前那张图，
遮罩只走 `MASK`。孤海把「带不带色」做成两个互斥的档位，这里只有一个开关：默认关，
开着才按编辑器里选的颜色和浓度刷进 `IMAGE`。两边都能要到同一张带色图，区别只是
默认值站在「干净」这一边。

**孔洞填充在编辑器里，而且是自动的**（孤海那支一样自动：勾上它的「填充孔洞」，抬笔后
自己在 `setTimeout` 里重算填充层，不用点按钮）。我们默认开着、每次抬笔补一遍。

落笔过程中看到的是**笔迹本身**，不是填充层 —— 孤海也是这么分的：画的时候用
`drawingPreviewPaint`（原始笔画），`pointerup` 之后才换成 `filledPaint`。所以洞里补上的
那一下会跳一格，那是抬笔后才有的动作。

它只补「被遮罩围死的洞」：灌水用 `alpha > 5` 当墙（跟孤海一字不差）、**灌水本身不膨胀**，所以
外缘不会越补越胖。墙的门槛别再往高里调 —— 用 128 的话，软边笔画围出来的圈会被边缘那圈
半透明当成「没画」，灌水顺着边上漏出去（实测 100% 软度 200px 笔宽的圈：`> 5` 补 41418 px，
`>= 128` 只补 13326 px）。早先是先膨胀 2 像素再灌水，好处是收笔时那条 1px 的缝也能补上，
代价是每抬一次笔遮罩就胖一圈；自动模式每次抬笔都跑，这个代价付不起，宁可少填。
填充只是**看得见的一层**：它每次都从原始笔画重算，不算笔画，撤销回退的是笔本身，
关掉开关立刻回到手画的样子。

不过**算完洞之后会把洞往笔迹里多吃 3 像素**（`growIntoWall`）。洞和笔迹的交界本来是
「实心 255 紧贴着抗锯齿的 alpha≈6」，中间夹一圈淡沟；在 50% 预览下、尤其白底图上，
那圈就是一道像虚线的浅痕。孤海没这个问题，是因为它把墙一起涂成实色（`rebuildSingleColorFill`
里除了「墙外的空白」全是 255），代价是笔迹边缘也变硬。我们只在**洞这一侧**补实，笔迹外缘
的软边照旧留着。多吃的那 3 像素只往「已经有颜色」的像素里长，不会推到空白处把遮罩撑胖。

笔尖圈是**深色垫底 + 白色细线**两道描边：只描白线的话，白底图上整个圈看不见。

**填充按颜色分开存，各跟各的笔画**（`fillLayers`）。以前是「所有颜色的洞合成一张、盖在所有笔画
最上面」，于是先画的红色圈填满之后，再换绿笔在红块上画，绿笔会被红洞整块盖掉。现在每色的洞跟
自己的色层一组，组与组之间按**这一色最后落笔的先后**排 —— 后画的那一组整体在上面：

| 你画的顺序 | 结果 |
|---|---|
| 先红圈 + 填满，后画绿笔 | 绿组最后落笔，绿笔压在红洞上，看得见 |
| 先绿块 + 填满，后画红圈 | 红组最后落笔，红洞连绿一起盖住，圈里整个变红 |

洞**只补「原本没遮住」的地方**：打开一张成品时那 9 个色层是按颜色拆开的碎片，对碎片灌水会把
碎片之间的小缝当洞，实测一张成品重开一次就能多出 5 万多像素的假洞、颜色越存越白。已经有遮罩的
区域一个像素都不碰，反复存盘的颜色也就稳了（实测四次存盘逐像素一致）。

（那个节点的下拉列表里不会出现成品名 —— 值是直接写进去的；核心只校验文件在不在，
所以照样跑得通。）

### 遮罩编辑器

点「编辑遮罩」（或者双击图）就打开一个全屏编辑器：画笔、橡皮、笔宽 / 软度 / 透明度三根滑条、
撤销重做、清空、反色、自动填充漏洞、九色板（它同时是笔色）都有，笔的用法和图像对比的橡皮擦是一套
（`[` `]` 改笔宽、`Shift` 加 `[` `]` 改软度、按住 `Alt` 加右键拖着调、右键或 `Ctrl`
反过来用当前的笔）。**软度默认 0**（硬笔）：抠头发丝、衣领这种地方硬边更好对，想糊开自己往上调。

**滚轮缩放画面，按住空格或中键拖动平移**（跟孤海一样：滚轮以指针为锚点，0.05 ~ 12 倍）。
缩放只改画面的 CSS transform，遮罩位图一个像素都不重算，所以放大后照样流畅；笔迹仍然落在
指针底下，越放大越好抠细节。

| 显示模式 | 看到什么 |
|---|---|
| 显示：彩色叠加（默认） | 遮罩区域盖一层当前颜色，浓度就是底栏那根透明度滑条 |
| 显示：仅遮罩 | 底图压暗，遮罩区域纯白 |
| 显示：原图 | 不画遮罩，方便对位置 |

**存盘写两个文件到 `input/clipspace/`，原图不动。** 官方的遮罩编辑器是把遮罩烧回
原图、覆盖 input 里那张文件（文件名末尾的 `[input]` 只是路径提示，不是文件名的一部分），
画错一次原图就没了；这里原图永远在，想重来就回到原图再画一次。

| 文件 | 内容 |
|---|---|
| `qg-src-<时间戳>.png` | 原图副本，只为了留住它自己的 alpha |
| `qg-painted-<原名>-<时间戳>.png` | 成品：RGB 是画面，alpha 是遮罩 |

两个文件用同一个 13 位时间戳配对（`qg_load_image.py` 里的 `PAINTED_NAME`）。读的时候
成品里的 alpha 被副本的 alpha 换掉，所以 `IMAGE` 是画之前那张图，遮罩只出现在 `MASK` 上。
成品名里带着原文件名，只是方便人认，不再单开输出槽。

**节点里的预览和编辑器里的底图看的是副本，不是成品。** 成品那张图的 alpha 就是遮罩，
浏览器一渲染遮罩区域就成了透明 —— 所以凡是「要看画面」的地方一律拿副本，遮罩另从
成品的 alpha 里读回来。二次编辑就是这样接着上次的遮罩改的。

**遮罩范围在预览里显示成一层固定的半透明绿**（`42, 210, 112` @ 50%，只是提示层，
不跟输出的颜色走），只画在节点面板的那张 canvas 上，源文件一个字节都不动。这一层和原图
是上下两层叠在一起的：原图照常显示，上面那张 canvas 只画刷过的地方，其余透明。
**不做 PNG 编码** —— 早先的版本把两层合成为一整张图再 `toBlob`，1 兆像素的图光编码就
1.1 秒（热态也要 90ms），而那张图只是为了让浏览器马上再解码回来显示。官方核心的遮罩
编辑器也是这个路子：遮罩是独立一层 canvas，靠 `opacity` / `mixBlendMode` 叠在画面上，
改颜色只写 RGB 三个字节。

> 同一套做法孤海也在用（它是 `painted-*` 三个文件）；区别是我们只写两个，而且原图
> 副本只被读 alpha，不参与输出。它的绿色预览是另一个做法：三层 `<img>` 叠着，绿层直接
> 复用原图 URL 加一串 CSS `filter` 染色，靠最上层那张「挖过洞的图」当遮罩。

预览的高度是**常数 200px**，跟图片多大、多长都没关系 —— 选一张 2560 × 3413 的竖图，
节点也不会被撑成一根细高条。图片在自己那块框里等比缩到装得下（`object-fit: contain`），
不裁切、也不回头改节点尺寸。想看仔细就双击进遮罩编辑器，那儿是全屏的。
两种画布都是同一块面板：经典画布和 Nodes 2.0 都能用。

### 输入 / 输出

| 输出 | 说明 |
|---|---|
| `IMAGE` | 图片本体。默认是画之前那张图（遮罩不进画面）；开了「输出带色图」则把编辑器里的多色带出来。关掉「保留透明通道」时是三通道 |
| `MASK` | 画上的地方 1、没画的地方 0；尺寸恒等于图片 |

只有这两个。宽、高、帧数本来就写在面板图下方（`1036 × 584`），文件名用字符串节点就能
拿到 —— 把它们做成输出槽，只是让人在画布上多接几根线。

## Image Crop + Rotate + Pad（裁剪 + 旋转 + 补边）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ImageCropRotatePad`）· 参考 ComfyUI-AusBoss（MIT）「Image Crop + Rotate + Pad 🆎」的用法，代码自写
<!-- QG-ORIGIN:END -->


载入一张图，在节点上的编辑面板里做**一次**旋转 / 裁切 / 补边，输出摆正并补好画布的画面，
外加一份标出「该生成哪里」的遮罩。

### 面板怎么用

| 操作 | 效果 |
|---|---|
| 拖画面 | 平移取景框里的画面 |
| 拖角 / 拖边 | 改裁切框 |
| 旋转 | 顺时针旋转（`rotation_degrees`，-180 ~ 180） |
| 拖画布边 | 给某一边补出 `fill_color` 的边（拖出来的就是 padding） |
| 比例 | `crop_aspect_ratio`：锁定裁切框比例，`free` 任意、`source` 跟随原图 |

面板上的改动会直接写回节点参数，所以保存、撤销、API 调用都走 ComfyUI 原生路径。

### 遮罩里有什么

`mask` 白的地方就是「可以让模型画」的地方：

- 补出来的边（padding）；
- 旋转留下的空角；
- 原图里**透过去**的地方（实心度不足 90% 的像素，比如抠图留下的透明边）。

不想让透明区域被当成待生成区域，把 `painted_area` 设成 `keep picture` —— 底下原样保留，
只靠遮罩标记。

### 缝合器

`stitcher` 是一份「怎么把生成结果贴回原图」的说明，接到下游的缝合节点
（AusBoss 的 Stitch Inpaint，或本插件将来搬过来的同类节点）就能自动对齐贴回。
`stitch_blend` 控制贴回的过渡带宽度，`stitch_grow` 控制贴回边界往哪偏。

### 出规则尺寸

`canvas_multiple`（Divisible by）把输出长宽凑成它的整数倍：有补边的那一侧多补几个像素，
没补边的那一侧就裁掉几个像素（两侧各裁一半）。要 8/16/32 整除的模型设这里，`1` = 关闭。
`resize_to_megapixels` + `megapixels` 可以再把结果缩到指定像素预算（与核心
Scale Image to Total Pixels 同语义）。

### 输入 / 输出

14 个必填 + 7 个可选，全部是画布上的参数；画面上常用的一些
（比如旋转、裁切、补边）藏在面板里，不会挤满节点。

| 输出 | 说明 |
|---|---|
| `image` | 变换后的图像 |
| `mask` | 待生成区域（补边 / 旋转空角 / 透明处） |
| `stitcher` | 缝合器（贴回原图用） |
| `original` | 变换前的原图 |
| `width` / `height` | 输出尺寸 |
| `prompt_image` | 给模型看的提示图（带待生成区域的示意） |

### 自定义比例预设（可选）

把插件根目录的 `qg_presets_example.json` 复制成 `qg_presets.json` 再改，
可以往比例下拉里加自己的 `W:H` 条目。文件里有坏条目只会警告一次并跳过，不影响节点注册。

## Outpaint Board（扩图画板）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_OutpaintBoard`）· 参考 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「外补画板（可视化）」的用法，代码自写
<!-- QG-ORIGIN:END -->

把画板往外扩，同时给出「该补画哪里」的遮罩。扩出来的尺寸、遮罩、预览三者同步，
源图像素是复制进去的，**绝不重采样**，图还钉在原位 —— 所以输出里属于原图的那一块与输入逐位相同。

### 面板怎么用

| 操作 | 效果 |
|---|---|
| 点边框外 | 那一侧吸到鼠标位置（点图像下面只改下补边，点右下角外侧则下和右一起改） |
| 拖边框 | 连续改那一侧，拉出去是扩、拉回来是缩 |
| 点已有的补边区 | 该侧补边收回到鼠标处（扩了能缩回去） |
| 滚轮 | 以鼠标为锚点缩放预览。**这是唯一的直接缩放途径** |
| 中键拖动 | 平移画板看局部，源图不会被拖出预览区 |
| 工具行下拉 | `适应`（默认）/ 12.5% / 25% / 50% / 100% |
| 工具行齿轮 | 参数收进右侧浮层，节点不会被一堆控件撑高 |

**扩边时缩放是钉死的**：点一下、拖一下只改画板，画面在屏幕上的位置和大小都不动。
可见范围就是上限 —— 想再扩，先滚轮缩小。

### 三条尺寸规则（顺序固定）

1. **单位** —— `pixels` 四个方向按像素；`percent` 左右按宽度、上下按高度。
2. **长边上限** —— `max_output_side > 0` 时**只削补边，图像既不裁剪也不缩放**。
   原图本身已经超限时补边全部取消并打印一行提示，而不是悄悄裁图。
3. **整除数** —— `divisible_by > 1` 时画布宽高**向上**取整到它的倍数，多出来的补在右边和下边，
   图仍然不动。

### 输出

| 输出 | 说明 |
|---|---|
| `image` | 补好边的画板，直接接 VAE Encode |
| `mask` | 补边区 = 1.0，原图区沿用输入遮罩（没接就是 0） |
| `has_padding` | 四边真的补上了才为 True，可以用它跳过下游节点 |

### 和常见同类实现的差别

| 方面 | 本节点 | 常见实现 |
|---|---|---|
| 扩边时缩放 | 钉死，只有滚轮 / 下拉能改 | 随画板自动收缩 |
| 缩小 | 点或拖都能把扩出来的边收回去 | 只能往外扩 |
| 参数位置 | 收进右侧浮层 | 铺在面板上 |
| 主色 | 琥珀橙 `#FFA23A` | 青色 |

## LoRA Loader

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_LoraLoader`）· ComfyUI-AusBoss（MIT）「LoRA Loader 🆎」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


一个节点管整摞 LoRA：接上 `MODEL`（可选接 `CLIP`），下面排开你要用的所有 LoRA，
输出打好补丁的模型和一行触发词。

### 每一行有什么

| 控件 | 作用 |
|---|---|
| 拖拽手柄 | 按住上下拖动，调整 LoRA 的应用顺序 |
| 开关 | 临时旁通这一行，不必删掉它 |
| 名字 / 选择器 | 点一下打开搜索框挑文件；名字太长会按设置省略 |
| 强度 | 直接在名字上左右拖动就能调，也可以点进数值框；旁边有中心零点强度条 |
| ⓘ | 悬停看预览图、底模、触发词，可顺手查 Civitai |

### 触发词

每个 LoRA 的触发词会自动汇总，**去重**后按 `trigger_separator`（默认 `, `）拼成一路 `triggers`
输出，直接接进提示词。也可以给任意一行**手填自己的触发词**。

有两个刻意的设计：

- 把某行强度调到 **0**，它的触发词**仍然保留** —— 这样对比「用 / 不用这个 LoRA」时只需改权重，提示词不用动。
- 因文件缺失**被跳过**的那一行，不加任何词。

### 整摞存成模板

强度条那一排的 ▤ 按钮可以把当前整摞 LoRA 存成命名模板（存在浏览器本地）。
之后在任何 LoRA Loader 上点开 ▤ 就能一键套用，也能删除。

### 吸收模型链上的 LoRA

齿轮菜单里的 **Absorb chain LoRAs** 会沿本节点的模型链往上下游走，把路上遇到的其它 LoRA 加载器
（包含 rgthree、JPS、Pixaroma 等插件的节点）的 LoRA 全部并进本节点，再把那些节点自动旁通 ——
**出图结果完全不变**，只是整摞 LoRA 集中到了一处管理。

前提是那些节点的 LoRA 不是从连线动态接进来的（例如 rgthree 的 Power Lora Loader 接了外部输入）；
这种情况菜单会提示你先断开。整摞 LoRA 也有行数上限，超出时会提示你先清理几行。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（必填） | `model` | 要打 LoRA 补丁的扩散模型 |
| 输入（必填） | `loras` | 序列化的 LoRA 栈，**由面板托管** —— 改行，不要改这个值 |
| 输入（可选） | `clip` | 不接的话 CLIP 强度会被忽略 |
| 输入（可选） | `trigger_separator` | 触发词之间的分隔符，默认 `, `；在齿轮菜单里改，画布上隐藏 |
| 输入（可选） | `on_missing` | 文件缺失时怎么办，见下 |
| 输出 | `model` | 按行顺序打完所有启用 LoRA 的模型 |
| 输出 | `clip` | 同样处理过的 CLIP |
| 输出 | `triggers` | 所有启用行的触发词，去重后拼成的一行字符串 |

### 文件找不到时

- LoRA **只是被移动过**（还在 `loras` 目录里、换了子文件夹）会在运行时按文件名自动找回来，不用管。
- **真的找不到**时，默认行为是**在采样前直接报错停下**，并在错误信息里点名是哪个文件 ——
  无人值守或脚本化跑图不会静默地少打一个 LoRA。
- 想让它在控制台警告一声然后跳过这一行，把齿轮菜单里的 **Stop on missing LoRA** 关掉即可
  （API 调用时对应 `on_missing: "skip"`）。

### 设置

齿轮按钮里是这个节点类型的偏好设置，存在浏览器本地，跟着你所有工作流走：

| 设置 | 默认 | 作用 |
|---|---|---|
| Default strength | 1.0 | 新加一行时的初始强度 |
| Strength step | 0.05 | 拖动与方向键的步长（按住 Shift 恒为 0.01） |
| Separate model / CLIP strength | 关 | 每行显示两个强度框，分别控制模型和 CLIP |
| Strength bars | 开 | 名字后面的中心零点强度条（青色向右为正，红色向左为负） |
| Trigger word separator | `, ` | 拼接 `triggers` 输出用的分隔符 |
| Stop on missing LoRA | 开 | 关掉后，文件缺失只警告并跳过 |
| Hide file extension | 开 | 名字不显示 `.safetensors` |
| Hide folder names | 开 | 只显示文件名（完整路径仍在提示里） |
| Civitai lookup button | 开 | 信息卡里提供「查 Civitai」按钮 |
| Long names | end | 名字太长时怎么省略；`middle` 会保留结尾的数字 |
| Scrub strength on the name | 开 | 在名字上左右拖动改强度（单击仍然是打开选择器） |
| Preview thumbnails | 开 | 悬停选择器时显示预览图 |

<!-- QG-ORIGIN:BEGIN -->

**设置点**给这条线起个名字，**获取点**在图的任何位置把名字取回来。两个节点都是虚拟的 ——
不进 prompt、不执行、不占显存，只在前端存在。

- **成对使用** —— 获取点的下拉里列的就是同图所有设置点的名字。名字重复时设置点会自动改成

  获取点：跳转到设置点、转换成普通连线
- **任意节点右键** —— 「添加 获取节点 / 添加 设置节点 / 将所有输出转换为 设置/获取」，
  选区里有多个节点就一起处理
- **连线右键** —— 「转换为 设置/获取」，一条真实连线原地变成一对
- **画布右键** —— 批量：把选中节点的输出全转成设置/获取，或者把选中的设置/获取转回连线
- **分享给别人时** —— 对方没装本插件的话，用「转换成普通连线」还原成普通线再存

## Workflow Switches（工作流开关）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_WorkflowSwitches`）· ComfyUI-AusBoss（MIT）「Workflow Switches 🆎」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


把一套工作流拆成几块，用一个节点统一切换。适合对比「开不开这一块」的效果、或者做「快速模式 / 全量模式」。
节点自身不运行，也不接任何线，纯粹是画布控制器。

### 建一个开关

1. 在画布上**选中一组节点**（比如放大节点 + 它的保存节点）。
2. 在开关卡片上点 `+ Switch`。
3. 起个名字（比如「高清放大」）。

之后这个开关就是这一组的 关 | 开 按钮。**关** 默认是旁通（bypass）这些节点，图照常往下传；
在设置里可以改成**静音**（mute，下游拿不到输入会停下）。

### 三种不同粒度的开关

| 类型 | 建在哪 | 控制什么 |
|---|---|---|
| 节点开关 | 选中任意若干节点 | 这一组节点的开/关 |
| 分组开关 | 选一个分组 | 整个分组的开/关 |
| 全局开关 | 设置里的分组策略 | 按「不分组 / 每个分组 / 按编号分组」批量生成 |

打开「**一次一个**」后，打开某一行会自动关掉其它行 —— 适合「两个放大模型二选一」这类场景。

### 当参数预设用

开关不只管开关，也能改参数：选中节点后把当前值存成「开」的一套、改成另一套再存成「关」的一套。
之后一键就能把 Steps 设成 8、打开某个 LoRA 行，而不需要真的旁通任何节点。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | —— | 无 |
| 输出 | —— | 无 |

开关状态存在节点自己的属性里，所以随工作流一起保存。

## 释放显存（跑图时腾显存）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_FreeMemory`）· ComfyUI-AusBoss（MIT）「Free Memory 🆎」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->

- **什么线都能穿** —— 图像、latent、模型、文本、数字；槽类型标 `*`，接哪都行

- **不打缓存** —— 跟别的节点一样只在输入变化时才重跑，下游的缓存不受影响

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `值` | 任意线。这个节点跑的时候清一次显存，然后值原样往下走 |
| 输出 | `值` | 一个字节都没动 |

控制台会打一行 `[QG-tools] Free Memory: unloaded models, emptied the model cache, ...`，
告诉你哪几步真的做了、哪几步被跳过。

## 加载文档（把 Markdown 读进工作流）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_MDReader`）· 作者自有插件 ComfyUI-MD-Reader（MIT）「MarkdownFileReader」，合并进来
<!-- QG-ORIGIN:END -->

把一个 `.md` / `.txt` 文件读成一路 `STRING`：提示词、说明文字、术语表写在文件里，
改文件就行，不用回画布上改文本框。文件放进 ComfyUI 的 `input` 目录就出现在下拉里，
选中之后节点下半部直接把文档显示出来。

- **两种取法** —— `plain` 把 Markdown 记号（`#`、`*`、`-`、`[]()`、表格竖线）剥掉，
  出来就是能直接当提示词的干净文本；`raw` 原样输出，给需要保留格式的场合
- **也能直接给绝对路径** —— 文档不在这几个目录里时，把完整路径填进 `custom_path`，
  填了就用它、盖过下拉的选择
- **文件变了才重跑** —— 按文件修改时间判断，文档没改就沿用缓存，不会让下游白算一遍
- **编码不乱** —— 依次按 UTF-8（带 / 不带 BOM）、GBK、Latin-1 试过去，中文文档不会读成乱码
- **记住上次选的文件** —— 换工作流、重开页面，下拉还停在你看的那一篇

### 节点上的预览

选中文件后，节点里就是一块可滚动的预览区：

- 顶栏四个按钮：**刷新文件列表**（重新扫目录，会提示找到几篇）、**放大查看**（Esc 关闭）、
  **复制当前看到的文本**、**在「渲染后的文档 / 输出的纯文本」之间切换**
- 底部一行状态：字符数 · 文件修改时间 · 当前视图
- 预览区跟着节点高度拉伸 —— 节点拖多高它就显示多少，新建时默认给到 380 × 360

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（必填） | `md_file` | 扫描到的文档列表：`input` 目录 4 层内，以及 ComfyUI 根目录下 `md` / `markdown` / `prompts` / `prompt` 目录 3 层内；认 `.md` `.markdown` `.mdown` `.mdx` `.txt`，最多列 500 个 |
| 输入（必填） | `mode` | `plain` 去记号的纯文本 / `raw` 原文 |
| 输入（可选） | `custom_path` | 绝对路径；填了就用它，盖过下拉 |
| 输出 | `text` | 文档正文（`STRING`，单元素） |

扫描会跳过 `.git`、`__pycache__`、`node_modules`、`venv`、`models`、`custom_nodes`、`web`、
`output` 这类目录，免得把依赖包自带的 README 全列进来。一个文档都没有时，下拉里只留
`<no document>`，节点会提示先放文件再点刷新。

## 任意切换（动态多输入开关）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_AnySwitch`）· 参考 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「GoohaiAnySwitch」的用法，代码自写
<!-- QG-ORIGIN:END -->


把任意数量的同类型输入接到节点上，它会输出**第一个非空、已连接的那个**——
接线时连几个，节点上的槽位就自动增减（最少 2 个、最多 16 个），中间的空槽会保留位置，
所以优先级稳定、不会因为中间断开而错位。

- **接兜底** —— 把「高清模型」接在最上面、「普通模型」接在下面；前者有就走前者，没有自动回落到后者
- **类型要一致** —— 所有输入必须是同一类型。混接（比如一个 IMAGE、一个 LATENT）节点会直接报错说清是哪两种类型，而不是把错的数据喂给下游

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（可选） | `any_01 … any_16` | 任意类型的输入，接到哪个就出现哪个；输出第一个非空 |
| 输出 | `any` | 第一个非空、已连接的输入（类型与输入一致，连线时槽位会标成具体类型如「图像」） |

## 存在判断（有没有东西过来）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Exists`）
<!-- QG-ORIGIN:END -->


问一句「上游到底有没有东西过来」，顺手把值原样传下去 —— 判定和透传一次办完：

- **判定** —— 有值输出真，没有输出假。输入槽是**可选**的，所以「没接线」本身就是
  一个能判断的状态，而不是执行前的一句报错
- **透传** —— 同一份值从「任意」原样出去，不用把链路拆成两条
- **什么算「没有」** —— 没接线、`None`、空文本 `""`、空列表 / 空字典、**全黑遮罩**、
  **全零潜空间**都算；**`0` 和 `False` 算有** —— 它们是有效数据，不是缺席；
  **全黑图像也算有** —— 那是一张有效的黑图，不是失踪
- **判定口径对齐孤海工具箱的「万能是否存在(GH)」** —— 遮罩上低于 `0.02` 的残差当噪声
  抹平后再判（Qwen Image 2.1 的 RGBA 存盘再读回来会带 1/255~3/255 的残差，预览是全黑的）。
  唯一的区别：**我们只判不改** —— 透传出去的值保持原样，不会真把那些像素抹成 0
- **典型接法** —— 「布尔」接到「是否判断」或「布尔开关」的条件上，「任意」接给那一支
  要用的下游：可选模型没加载时走兜底，而不是让整张图报错

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（可选） | `任意` | 什么都接；不接 / 空值就是这个节点要报告的状态 |
| 输出 | `任意` | 原样透传进来的值（没接时为空） |
| 输出 | `布尔` | 有值真、没有假 |

> 输入是「可选」不是「必填」，这点是设计核心：必填的话 ComfyUI 会在执行前就报
> 「缺少输入」，这个节点永远没有机会输出假。

## 路由阻断（这条线走不走）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_RouteBlocker`）· 参考 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「GoohaiRouteBlocker」的用法，代码自写
<!-- QG-ORIGIN:END -->


串在线路中间的一个开关 —— 通过时它等于一根导线，阻断时按你选的方式处理：

- **仅输出空值** —— 值换成空，下游**照常执行**，由它自己处理空值。适合「关掉这一段附加

- **中断后续分支** —— 输出 ComfyUI 原生的执行阻断信号，下游节点**被静默跳过**，等于
  程序化地给这条线按了 Ctrl+M；图里其它分支照跑
- **可以接上游** —— 「是否阻断」是个布尔输入，接布尔开关、比较节点、或另一个「存在判断」
  都行，让流程自己决定走不走
- **打开就不花钱** —— 开关打开时，这条线**上游的所有节点都不会被求值**。所以「条件不满足
  就整段不跑」不用再靠把采样器拖出来手动绕过，掐在这里就行：贵的分支一个字节都不花

和「是否判断」的分工很清楚：那个是**二选一、只走一条**；这个是**走不走、走到哪为止**，
不用把线路拆成两股，串在任意位置就行。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `是否阻断` | 关着＝原样放行；打开＝按「阻断模式」处理。可接上游布尔 |
| 输入 | `阻断模式` | `仅输出空值` / `中断后续分支` |
| 输入（可选） | `任意` | 要放行或被阻断的值，什么都接；不接时输出就是空 |
| 输出 | `任意` | 通过时是原值，阻断时是空值或执行阻断信号 |

## 字符串切换（两段提示词二选一）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_StringSwitch`）· 参考 ComfyUI-Crystools（GPL-3.0）「Switch string [Crystools]」的用法，代码自写
<!-- QG-ORIGIN:END -->


同一个节点上放两版提示词，用一个布尔切换输出哪一版 —— 做 A/B 试穿、换风格、开关附加描述时，
不用为每段文字各拉一个文本节点、再各连一根线。

- **两段文本直接写在节点上** —— 上方是「真时文本」，下方是「假时文本」，都不用接线
- **想动态也能接线** —— 把任一文本框拖成输入槽（或直接连上），上游的值会覆盖框里写的
- **没选中的那一路不执行** —— 两个输入都声明了懒执行，挂在假分支上的 LLM 调用、读文件节点不会白跑
- 与「是否判断」的分工：那个切的是**任意类型的槽**，这个切的是**写在节点里的字符串**

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `是否为真` | 布尔条件 |
| 输入 | `真时文本` / `假时文本` | 两段文本；既是可编辑框，也能连线上游 |
| 输出 | `字符串` | 被选中的那一段 |

> 思路参考 Crystools 的 `Switch string`，按本插件约定重写（显示名、中文 tooltip、惰性判断都不同）。

|---|---|---|
| 输入 | `标签` | 卡片上显示的名字，留空则显示「开 / 关」。没有输入槽，双击卡片改 |
| 输出 | `布尔值` | 开关状态，可同时连多个下游；槽名画在卡片上方，不会被卡片压住 |

## 数值（整数 / 浮点合一）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Number`）
<!-- QG-ORIGIN:END -->


一个数字，一张卡片：左边一行小字「值」，右边就是一个数字框 ——
**左右拖动改、单击直接输入、右边上下箭头按步进调**（Shift 细调），
跟包里 LoRA 加载器的强度框是同一件东西。

- **类型在标题栏齿轮里** —— `?` 左边那枚齿轮点开是「数值设置」，整数 / 浮点数二选一。
  二选一占一整行下拉太浪费，也容易被动到，所以收进齿轮里
- **类型决定输出** —— 选整数就输出 `INT`（小数四舍五入掉），选浮点就输出 `FLOAT`；
  输出槽固定是「任意」（`*`），所以两种模式都接得进 `FLOAT` 口（比如 LoRA 强度）
- **步长跟着类型走** —— 整数按 1 走、框里不显示小数点；浮点按 0.1 走、显示两位小数
- **切回整数会取整** —— 卡片里不会有「显示 4、实际 3.7」这种别扭状态
- **值存法跟原生一样** —— 存档、撤销、复制粘贴、API 导出全跟 ComfyUI 自带节点一致
- 一个节点顶两个，不用再纠结拖「整数」还是「浮点数」

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `类型` | 整数 / 浮点数，在标题栏齿轮里切换 |
| 输入 | `值` | 数值本身，拖动 / 单击输入 / 箭头步进 |
| 输出 | `数值` | 类型由「类型」决定，可同时连多个下游 |

> 输出槽声明为「任意」（`*`），因为 ComfyUI 的类型是类级静态的、运行时改不了，真正的
> 类型由实际返回值决定。**别图好看把它改成 `INT` / `FLOAT`** —— 前端会拿它做连线校验，
> 整数模式就再也接不进 `FLOAT` 输入（LoRA 强度），而且 `connect()` 是**静默失败**
> （不报错、也不建线），最难查。

## 数值滑条（范围自己定）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Slider`）
<!-- QG-ORIGIN:END -->


一根滑条挑一个数。跟「数值」的区别只有一个：那边是纯数字框，这边是一根**拖得动**
的滑条，而且**范围自己定**（最小 / 最大），适合「强度 0–1」「步数 20–50」这种有明确
上下界的参数。要精确到某一位，**点右端的数字直接敲**也行。

**开箱就是 0 – 1、一格 0.1、输出小数** —— 也就是 LoRA 强度 / 权重 / 去噪强度最常见
的那个区间，新建节点拖两下就能用。要当计数用，在齿轮里把范围改成 0 – 100、类型改成
整数就行。

卡片就一行，从左到右就是用法：

| 位置 | 内容 | 用途 |
|---|---|---|
| 左 | 滑条轨道 | 唯一的值输入：拖到哪儿值就是多少（一格 = 步长），铺满整行 |
| 中 | 当前值 | 实时读数，小数位跟着步长走（步长 0.25 就显示两位）；**点一下就能直接输入**，回车确认、Esc 取消 |
| 右 | 齿轮 | 点开「滑条设置」：类型、最小、最大、步长都在这儿 |

- **范围在齿轮里** —— 最小 / 最大一次设好就不常动，所以不占卡片；改完滑条立刻跟着
  伸缩，填反了自动对调
- **类型也在齿轮里** —— 整数 / 浮点数二选一，外加**步长**（浮点模式每格多少，默认
  0.1 就是一位小数；0.01 就是两位）
- **整数模式**：滑条一格走 1、读数不带小数、切过去时小数会被四舍五入掉
- **浮点模式**：滑条一格走「步长」，读数的小数位跟着步长走
- **类型决定输出** —— 选整数输出 `INT`、选浮点输出 `FLOAT`；输出槽固定是「任意」，
  所以两种模式都接得进 LoRA 强度那种 `FLOAT` 口（当前是哪种，看右边读数有没有小数位）
- **超范围按两端算** —— 无论是拖滑条还是别的插件塞进来的值，出去时都夹在最小值 /
  最大值之间；把范围收窄时，现有的值也会被夹回来（不会出现「滑条顶在右端、输出
  却是 80」）
- 前后端取整规则一致（`floor(x + 0.5)` ↔ `Math.round`），不会出现「卡片显示 1、输出 0」
- **数值可以直接敲** —— 点右端的读数弹一个输入框（带出当前值），回车确认、Esc 取消；
  打进去的数照样按步长对齐、夹进范围，跟拖出来的没区别
- 轨道**又粗又长**（12px 高 + 20px 滑块），节点开箱 320×58 —— 跟「布尔开关」
  **完全一样大**，两个摆一排是齐平的；读数只占「范围里最大的那个数」那么宽的格子
  （默认 0–1 只有 22px），轨道一直铺到它左缘前 4px（约 237px）
- 画布上这整行是**直接画出来的**（跟布尔开关同一套做法），所以节点高度能压到 58；
  Nodes 2.0 下换成 DOM 卡片，高度由卡片自己撑

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `值` | 当前数值，拖滑条改 |
| 输入 | `最小` | 滑条左端，在齿轮里设 |
| 输入 | `最大` | 滑条右端，在齿轮里设 |
| 输入 | `类型` | 整数 / 浮点数，在齿轮里切 |
| 输入 | `步长` | 浮点模式每格多少（整数模式固定 1），在齿轮里调 |
| 输出 | `数值` | 类型由「类型」决定，可同时连多个下游 |

> 卡片只留了滑条这一个入口：类型、范围、步长都在齿轮菜单里，五个控件本身在画布上
> 收起来了 —— 存档结构不变，读老工作流照样对得上。

## 数学运算（一行表达式）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_Math`）
<!-- QG-ORIGIN:END -->


卡片上只有一行：写算式。变量是节点左侧的 `a`、`b`、`c`……
需要「宽按高度算」「百分比」「勾股」这类地方，一行写完就行，不用串三个节点。

```
round(a / b * 2, 2)        # 比例算尺寸，留两位
sqrt(a**2 + b**2)          # 勾股
100 * 2                    # 常数直接写进表达式
a if a > b else b          # 取大的那个
```

- **变量只接上游** —— 左上角默认 `a` / `b` / `c` 三个槽，**接满一个就自己长出下一个**（最多 26 个），
  整数（宽度、高度、帧数）、小数、布尔都能接。**没连线时按 0 算** —— 要写常数直接写进表达式，
  卡片上没有数字框
- **一个结果三种给法** —— `数值`（小数）、`整数`（四舍五入）、`布尔`（非零为真），
  写比较式 `a > b` 时直接把 `布尔` 当条件接到下游
- **函数用法有专门的手册** —— 📖 [数学运算 · 表达式与函数手册](https://github.com/live1617/ComfyUI-QG-tools/blob/main/docs/math.md)：
  每个函数做什么、怎么用、有什么上限，都在里面；节点上的 `?` 是速查版
- **算错会说话** —— 语法错、未知名字、除零都会报出原始算式和原因，不会静默返回 0
- **只解析不执行** —— 表达式走语法树白名单，别人分享的工作流带不进代码

| 类别 | 用法 |
|---|---|
| 运算符 | `+` `-` `*` `/` `//`（整除） `%`（取余） `**`（幂） |
| 比较 / 逻辑 | `==` `!=` `>` `<` `>=` `<=`，`and` `or` `not` |
| 条件 | `a if a > b else b` |
| 常量 | `pi` `e` `tau` |
| 取整 | `round(x, n)` `floor` `ceil` `trunc` `abs` `sign` |
| 数值 | `min` `max` `sum` `pow` `sqrt` `log` `log2` `log10` `exp` `hypot` |
| 三角 | `sin` `cos` `tan` `asin` `acos` `atan` `atan2`，`degrees` / `radians` 换角度 |
| 其他 | `int` `float` `bool` `factorial` `gcd` `lcm` `fmod` `copysign` |

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `表达式` | 算式本身，留空输出 0 |
| 输入（可选） | `a` … `z` | 自动增长的变量槽，默认露出 3 个；整数 / 小数 / 布尔都能接，没连线按 0 |
| 输出 | `数值` / `整数` / `布尔` | 同一个结果的三种形态 |

> `^` 是**按位异或**（Python 语义），幂请写 `**`。全角的 `（ ）＋ × ÷` 和比例写法 `3：4` 会自动归一。
> 每个函数的完整用法和例子见 [docs/math.md](https://github.com/live1617/ComfyUI-QG-tools/blob/main/docs/math.md)。

## 双式数学运算（两行表达式，共用五个变量）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_DualMath`）· 参考 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「数学运算 孤海」的用法，代码自写
<!-- QG-ORIGIN:END -->

两行算式各写各的，但共用左侧同一组变量 `a`、`b`、`c`、`d`、`f`：一个节点同时给出
两路小数和两路整数，适合「宽和高各算一次」「种子和强度各算一次」这类成对的计算，
不用串两个数学节点。表达式留空就是 0。

```
a * 2                          # 第一行：宽度翻倍
round(sqrt(a**2 + b**2), 2)   # 第二行：勾股，留两位
```

- **变量是 a b c d f** —— 整数 / 小数 / 布尔 / 文本都能接，没接线按 0 算；
  故意跳过 `e`，让 `pi` / `e` / `tau` 这些数学常量照常可用
- **一行结果两种给法** —— 每行都给「浮点 + 整数」，整数按四舍五入（`.5` 远离零）
  并限制在 INT32 范围内；算出文本时数值槽给 0
- **第五路是语法速查** —— 一段英文文本，可以接到任意显示文本的节点上随时查函数表
- **不用 `eval`** —— 表达式走包内白名单求值器（与上面「数学运算」同一套），属性访问、
  `__import__`、任意函数调用都会被拒绝，报错里会点名是哪一行表达式

> 概念参考孤海工具箱「数学运算 孤海」的两行表达式形态，代码为本包自写，
> 键名、说明与报错全部英文。

## 长短边（长边 / 短边 / 宽高比）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_LongShortSide`）· 参考 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「长边短边」的用法，代码自写
<!-- QG-ORIGIN:END -->

三个输入全是可选的：`图像`、`宽度`、`高度`。**接了图像就按图像尺寸算**，宽高输入让位；
没接图像才用那两个整数。输出 `长边`、`短边` 和 `比值`（宽 / 高）。

```
1920 × 1080  →  长边 1920、短边 1080、比值 1.777…
1080 × 1920  →  长边 1920、短边 1080、比值 0.5625
只接宽度 100 →  长边 100、短边 100、比值 0
```

- **只给一边时两边同值、比值给 0** —— 没有真实宽高比可报，不编一个 1.0 出来
- **尺寸兜底安全** —— 什么都没接、图像读不出形状、或值不是数字，一律返回 `(0, 0, 0.0)`，
  不会把工作流整条炸掉；异常会在控制台留一条英文提示
- **和另外两个尺寸节点分工不同** —— `图像或 Latent 尺寸` 给宽 / 高 / 帧数，
  `比例与分辨率` 给比例串和目标尺寸，这个只量「已经有的是多大」

> 概念参考孤海工具箱「长边短边」，代码为本包自写，键名、说明与提示全部英文。

## 种子（一个数字单独走一根线）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：搬运（`QG_Seed`）· ComfyUI-AusBoss + rgthree-comfy（MIT）「Seed 🆎 / Seed」，只改类名 / 分类 / 显示名 / 中文文案
<!-- QG-ORIGIN:END -->


把种子从采样器里**摘出来单独放**：一根 `INT` 线喂给好几个采样器，改一处全部跟着变；
回头想复现某张图，用的哪枚种子就摆在那儿。

卡片从上到下就是一块：大号数字、下面「随机值 / 固定 / Step」三选一、
最底下「新种子 / 用上次 / 历史」。

- **随机值** —— 每次排队之后重新抽一枚，范围 0 – 2⁵⁰−1（故意不铺到 2⁶⁴，
  再大 JS 的双精度就丢位了）。新建的节点默认就是这一档
- **手输别超过 2⁵³** —— 框里的数在浏览器里是双精度浮点，填更大的值会被悄悄取整；
  上限虽然写的是 2⁶⁴−1，实用区间就在 2⁵³ 以内（随机抽取本来就只到 2⁵⁰）
- **固定** —— 永远用框里这一个
- **Step +1 / −1** —— 每次排队之后加一或减一，扫一段连续区间时用
- **它记得自己真正跑过什么** —— 随机值模式一排队，框里的数字就换成下一枚了，
  所以「刚出的那张用的哪枚」光看框是看不出来的。节点每次运行会把**实际用的值**
  回传：底下一行「上次运行」显示它，「用上次」把它填回框里并切成固定，
  「历史」菜单存最近 8 枚，点一条就填回并固定。历史跟着工作流一起存
- **老工作流照样开** —— v0.8.4 及以前用的是 `-1 / -2 / -3` 哨兵值，
  加载时前端翻译成「模式 + 具体种子」，所以现在种子永远是非负整数

## 颜色校正（六个滑条走完调色）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ColorCorrect`）· 参考 comfyui-art-venture（MIT）「ColorCorrect」的用法，代码自写
<!-- QG-ORIGIN:END -->

六个滑条就是一次完整的调色，不用串一长串节点。它们按摄影调色的顺序依次作用：

**色温 → 明度 → 对比度 → 伽马 → 饱和度 → 色调**

- **温度** —— 冷暖。负值加蓝、正值加黄。三通道增益按 Rec.709 亮度权重做过归一化，
  **调它只变色、不会顺带把画面调亮调暗**
- **色调** —— 整张图的色相旋转，±180 是一整圈。走 HSV 只转 H，饱和度和明度不动，
  **纯红转 120 度就是纯绿**，不会转出一片灰
- **明度 / 对比度** —— 明度是整体乘系数（-100 全黑、+100 亮度翻倍）；
  对比度绕中灰 0.5 拉伸（-100 全片变成 0.5 灰）
- **饱和度** —— 按亮度做混合，**-100 是纯黑白而且亮度不变**，+100 色彩浓度翻倍
- **伽马** —— 只动中间调，两头不动。想提亮暗部又不想冲掉高光时，比直接调明度好用

全程 float 直算：没有 8bit 往返、不逐帧转 PIL、不依赖 OpenCV，所以渐变不出色阶，
整批一次算完。参数回到默认值就跳过那一步 —— 伽马 1.0、其余全 0 时，
输出与输入**逐字节相同**。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` | 批次一次处理完；有 alpha 通道时原样保留 |
| 输入 | `温度` / `色调` / `明度` / `对比度` / `饱和度` / `伽马` | 见上，六个参数互不干扰，任意组合 |
| 输出 | `图像` | 与输入同尺寸、同批次数 |

## 颜色匹配（把一张图的配色搬到另一张）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ColorMatch`）
<!-- QG-ORIGIN:END -->

给它一张目标图和一张参考图，它把参考图的**色调、对比、整体色偏**搬过来，
目标图自己的构图和明暗层次保留。典型用法：把生成图和一张实拍素材的色调对齐、
给一段视频统一成同一个影调、把不同来源的素材剪在一起时统一配色。

**九种方法**（另加一个仅均值），按「换色换到多狠」排列：

| 方法 | 干了什么 | 什么时候用 |
|---|---|---|
| **小波变换** | Haar 小波分解 3 层，只把**最低频子带**的均值 / 方差对齐到参考，细节子带原样保留 | 素材细节多（布料、皮肤、毛发、文字）。换色调但纹理、边缘、噪点全不动 |
| **自适应实例统一化** | AdaIN 的逐通道 `(x-μ)/σ`，**在 sRGB 上**做 | 同源素材、风格化迁移。比莱因哈德更"硬"，不分离亮度与色度 |
| **最大均值差异** | RBF 核下最小化 MMD²(P′,Q)，迭代 60 步求出一组仿射映射 | 参考图的分布是多峰的、不像高斯时，比协方差法更贴 |
| **直方图匹配** | 逐通道按分位数把分布重排成参考的（CDF 匹配） | 要"完全一致"时。均值方差偏斜全对上，也最容易失真 |
| **莱因哈德色彩迁移** | 转到 CIELAB 后逐通道 `(x-μ)/σ` 对齐（Reinhard 2001） | **默认就用它**。亮度和色度解耦，改色不改明暗层次 |
| **多元高斯分布** | LAB 上做 3×3 协方差匹配（Pitié 2007 线性 MKL 的核心：白化再着色） | 修色偏最干净。比逐通道多照顾通道之间的相关性 |
| **直方图匹配-多元高斯分布-直方图匹配** | 三步串联：先把边缘分布拉近，再纠正相关性，最后直方图收尾 | 要边缘分布也对得很准。比单次直方图稳一点 |
| **直方图匹配-最大均值差异-直方图匹配** | 同上，中段换成核均值匹配 | 同上，且参考分布明显非高斯 |
| **Reinhard Lab GPU算法** | 与莱因哈德**同一个数学**，但走整批 4D 张量广播，没有逐帧循环 | 大图、长批次、跑在 GPU 上时更快。结果与莱因哈德逐像素一致 |
| **仅均值** | 只搬平均色，不动对比度 | 最保守。只想换掉整体色偏、不想动观感时 |

几个实现上的取舍：

- **小波只动低频**是有意的 —— 连细节子带一起匹配会把纹理改掉，那就成"重绘"了
- **MMD 求的是仿射映射**，不是逐像素核回归。后者数学上更"正宗"，但 E[Y|X] 的方差
  不可能大于 Y 的方差，实测输出 σ 只剩参考的四成，画面发灰；仿射版一阶 / 二阶统计
  都对得上，图像自身的局部结构也原样保留
- **"直方图匹配-…-直方图匹配"里中间那步的参考不变**，三步都对着同一张参考图，
  不是逐级传递
- **出口不再硬裁** —— 匹配后落到 sRGB 外面的颜色，沿 LCh 的 C 轴缩饱和度（色相与
  明度都不动）。逐通道 clamp 会改掉三原色比例，也就是**改色相**（实测饱和色偏 2–8°），
  这是 W3C 色域映射指南明确要求避免的
- **源侧统计量有下限** —— 目标图本身很平（雾、纯色背景、欠曝暗部）时，σ 会小到
  σ参考/σ源 放大几十倍，噪声和色阶一起炸出来。下限设成归一化 L 的 2%（约 5/255），
  实测同一张近纯色图：无下限偏离 0.12，有下限 0.013
- **遮罩有两个作用，别混** —— 一个是「结果作用在哪」，一个是「统计量从哪取」。
  后者是 Photoshop 匹配颜色的「使用选区计算颜色」：把主体贴进新背景时，背景像素
  不该参与目标侧的均值 / 协方差，否则主体统计被稀释。实测一张主体在左、右半是
  强绿的图，不限定统计时结果被带偏 0.17（归一化 Lab），限定后精确落到参考均值
- **参考图也能单独接遮罩** —— 参考图里有大片无关内容（天空、水面、水印、字幕）时，
  只让选中的区域参与统计。实测参考图左半暖橙、右半冷蓝，全图统计会把结果拉到
  中间（b −0.06），只在左半统计后 b 升到 0.21、贴着左半的真实值
- **细节回填补的是差额，不是原值** —— 直方图匹配把低对比素材拉宽时，颗粒和噪声
  会被一起放大（文献里叫 grain effect，实测高频能量 0.047 → 0.086）；反过来压缩
  时细节又被抹平。按「原图高频 − 结果高频」补，两种方向都能还原，且差额逐通道去
  均值，实测 sRGB 通道均值变化 < 1e-4，只动纹理不动明暗
- **小波变换不吃统计遮罩** —— 它是逐图对齐低频子带，本来就不统计像素分布，
  所以 `遮罩用途` / `参考遮罩` 对它只影响「作用区域」，不影响匹配本身

通用参数：

- **强度** —— 结果与原图的线性混合。0 = 原图，1 = 完全匹配，**0.5 左右通常最自然**
  （留一半原图的味道）。想做「轻微统一影调」就别拉到 1
- **参考取帧** —— 参考图是批次时：`全部合并`（所有帧并成一个样本池统计，最稳）/
  `仅第一帧` / `逐帧对应`（参考帧数不够就循环取）
- **目标统计** —— 目标图是批次时源侧统计怎么算：`逐帧`（每帧各算一套，单张图最贴）/
  `全批统一`（整批合成一套，帧与帧之间的相对差异被保留，**视频不会闪**）。
  视频 / 序列 / AnimateDiff 一律用 `全批统一`；只有一帧时两者等价
- **匹配范围** —— `全部`（明暗和色度都换）/ `仅色度`（保留原图的明暗层次，只换色调）/
  `仅明暗`（保留原图色调，只换对比度与整体亮度）。合成、只想统一影调时很有用
- **遮罩用途** —— `仅结果`（只决定作用区域，统计量仍取全图）/ `也限定目标统计`
  （统计量也只从遮罩内取）。**把主体贴进别的背景时用后者**，背景不会再稀释主体统计
- **细节回填** —— 把高频（纹理、颗粒、边缘锐度）还原到原图的水平。直方图匹配把
  渐变拉成色块、或者把低对比素材的噪点拉炸时调到 0.3–0.6；0 = 不管
- **遮罩羽化** —— 遮罩边缘的高斯羽化宽度（像素），0 = 硬边。接遮罩做局部换色时
  设 8–32，接缝会消失
- **遮罩** —— **作用区域**：白色处应用匹配，黑色处保留原图。做局部换色、
  或者只想统一背景色调时接一张遮罩即可
- **参考遮罩**（可选）—— **参考图上的统计区域**：只有白色处的像素参与统计。
  参考图里有大片无关内容（天空、背景、水印）时接一张，配色不会被它们带偏

参考图**不需要和目标图同尺寸** —— 取的是统计量，不是逐像素对应。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` | 要改的目标图；批次逐帧处理，有 alpha 通道时原样保留 |
| 输入 | `参考图像` | 配色从它身上取，尺寸随意 |
| 输入 | `方法` | 九种 + 仅均值，见上表，默认「莱因哈德色彩迁移」 |
| 输入 | `强度` | 0–1，默认 1.0 |
| 输入 | `参考取帧` | 全部合并 / 仅第一帧 / 逐帧对应，默认全部合并 |
| 输入 | `目标统计` | 逐帧 / 全批统一，默认逐帧 |
| 输入 | `匹配范围` | 全部 / 仅色度 / 仅明暗，默认全部 |
| 输入 | `遮罩羽化` | 0–256 像素，默认 0（硬边） |
| 输入 | `遮罩用途` | 仅结果 / 也限定目标统计，默认仅结果 |
| 输入 | `细节回填` | 0–1，默认 0（不补） |
| 输入 | `遮罩`（可选） | 作用区域，不接就是全图 |
| 输入 | `参考遮罩`（可选） | 参考图上的统计区域，不接就是整张参考图 |
| 输出 | `图像` | 与目标图同尺寸、同批次数 |

全程 float 直算，LAB 走 sRGB → 线性 → XYZ → Lab（D65），出界颜色缩 chroma 后再
clamp 回 `[0,1]`，中间不做 8bit 往返，所以渐变不出色阶。小波用正交归一化 Haar，
正逆变换往返误差在 `1e-7` 量级。

## 遮罩混合运算

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_MaskBlend`）· 作者自有插件 ComfyUI-QG-Multipack v0.1.0（GPL-3.0-or-later）「QG_MaskBlend」，合并进来
<!-- QG-ORIGIN:END -->

两张遮罩走布尔运算，再按 BBOX 规则把结果的外接框画成纯白矩形，顺带报出矩形的宽高——要接「出图尺寸」时不用另外去量。

| 模式 | 做什么 |
|---|---|
| 相加 / 相减 / 相交 / 排除 | 逐像素。排除是 NOR（两张都不覆盖的地方），不是 XOR |
| 取左 / 右 / 上 / 下半边 | 比两张遮罩的实际范围，在较近的那条边切一刀，只留遮罩 1 的那一半 |

BBOX 六档：关闭（原样输出混合遮罩，宽高仍按外接框报）、原始比例、长边正方形、短边正方形、按宽度正方形、按高度正方形。对齐方式（左 / 右 / 居中 / 上 / 下）决定新矩形落在哪；矩形越出画布时会平移进画面，**报的宽高就是实际画出来的尺寸**，不虚报。

- 两张遮罩尺寸不同会自动缩放，不会报「尺寸必须相同」。
- 一批多帧按**所有帧**的整体范围算外接框，不是只看第 0 帧；BBOX 模式下每帧画同一个矩形。
- 两个入口都没接时返回 1×1 空遮罩和 0/0，不硬凑一个假尺寸。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | 遮罩 1 / 遮罩 2 | 可选。画布以遮罩 1 为准；遮罩 2 不接按同尺寸全黑处理 |
| 输出 | 遮罩 / 宽度 / 高度 | 槽名 `mask` / `width` / `height` |

> 与「遮罩拼接」不是一回事：那个把两张遮罩并排拼成更大的画布，这个做逐像素运算再出外接框。两者并存。

## 遮罩分析

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_MaskAnalysis`）· 作者自有插件 ComfyUI-QG-Multipack v0.1.0（GPL-3.0-or-later）「QG_MaskAnalysis」，合并进来
<!-- QG-ORIGIN:END -->

量出遮罩非零区域的框，四条边各按百分比往外推或往里收，把结果填成纯白矩形，同时报出画布尺寸、矩形尺寸和矩形中心——接「出图尺寸」「居中放置」这类下游时不用另外量。

- 百分比按**该条边所在轴**的原始框尺寸换算：上下按框高、左右按框宽。正数往外推，负数往里收。
- 🔴 收缩保护与「孤海-遮罩分析」逐项对齐：它拿「两侧百分比之和」和「0.9 × 框像素数」比，量纲并不一致，压缩时还会把另一侧的正扩展吞成 0。看着像 bug，但为了让同一组参数在两个节点之间能直接互换，**故意保留**、不擅自修正。
- 有效像素按 `>= 0.5` 判定，软边遮罩里更暗的部分不计入框。
- 一批多帧按**所有帧**的整体范围算一个框，输出保留全部帧，每帧画同一个矩形（不塌成第 0 帧）。
- 全黑遮罩不再假装有尺寸：框宽高如实报 0，中心给画布中心。
- 框超出画布时先钳进画面，**报的宽高就是实际画出来的尺寸**。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `遮罩` | 要量的遮罩。2D / 3D / 4D 都收，统一按 3D 输出 |
| 输入 | `上扩百分比` / `下扩百分比` / `左扩百分比` / `右扩百分比` | -90 ~ 1000，默认 0 |
| 输出 | `遮罩` / `画布宽` / `画布高` / `遮罩宽` / `遮罩高` / `遮罩中心x` / `遮罩中心y` | 槽名 `mask` / `canvas_width` / `canvas_height` / `mask_width` / `mask_height` / `center_x` / `center_y` |

> 与「遮罩裁剪」「遮罩对齐」不是一回事：那两个一个按遮罩裁出图、一个把遮罩平移对齐；这个只量尺寸，输出的是填满矩形的纯白遮罩和坐标，不碰原图也不移动内容。

## 遮罩检测（有效面积够不够）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_MaskDetect`）· 作者自有插件 ComfyUI-QG-Multipack v0.1.0（GPL-3.0-or-later）「QG_MaskDetect」，合并进来
<!-- QG-ORIGIN:END -->

一条遮罩进去、一个布尔出来：这块遮罩够不够大，值不值得往下跑。接「如果否则」「路由阻断」这类节点当条件，省掉拿一张空遮罩跑完整条链。

- **有效像素是严格 > 0.5** —— 本包其余节点惯用 `>= 0.5`，这里故意不套用，与参考节点保持一致。
- **占比按整批合算** —— `squeeze()` 之后所有帧共用一个分母，不是逐帧判断。10 帧里 1 帧有内容、9 帧全黑，给的是 10%，不是 True。
- **过滤最小值填 0 跳过面积判断** —— 只要有一个有效像素就 True，用来问「有没有」而不是「够不够」。
- **全黑恒 False** —— 阈值填多少都一样。
- 占比以百分比表示（0 ~ 10），默认 3.0。

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `遮罩` | 要检测的遮罩，2D ~ 5D 都收 |
| 输入 | `过滤最小值` | 0 ~ 10，默认 3.0；填 0 只判断有没有有效像素 |
| 输出 | `是否存在遮罩` | 布尔，槽名 `has_mask` |

> **和「存在判断」不是一回事**：那个问的是「有没有值到达」（任何类型都收，遮罩最大值低于 0.02 也算空、latent 全零也算空），用来给「什么都没接」当条件；这个只收遮罩，问的是「够不够大」（0.5 硬切 + 可调面积百分比），用来给「遮罩太小不值得跑」当条件。

## 遮罩精修

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_MaskRefine`）· 参考 ComfyUI-AusBoss（MIT）「Mask Refine 🆎」的用法，代码自写
<!-- QG-ORIGIN:END -->


把一张遮罩按**固定顺序**修一遍，顺序是定死的，不用自己拼节点：

`扩缩 → 补洞 → 平滑 → 羽化 → 边缘精修 → 色阶`

- **扩缩** —— 按整像素往外长或往里收，可分离 max / min 池化，跑多远都是两趟
- **补洞** —— 只补被围住的窟窿，碰到画面边缘的缺口永远不算洞；`最大补洞` 按面积百分比限制，2% 能补掉随手一笔的缝但保住你故意没涂的人
- **平滑** —— 二值化 → 高斯 → 再二值化，**只把差值加回去**：锯齿被化掉了，软边遮罩原来的 alpha 一点没丢
- **羽化** —— 可分离高斯，0 保持硬边
- **边缘精修** —— 拿导向图把边吸附到发丝、衣领上；导向滤波要 `opencv-contrib-python`，抠像要 `pymatting`，没装只会报一句明确的缺依赖提示，不影响其它设置
- **色阶** —— 黑白场收一遍，把软分割留下的灰雾抹干净

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `遮罩` | BHW 遮罩，白＝选中 |
| 输入 | `扩缩` / `羽化` | 像素级放大缩小、高斯羽化强度 |
| 输入 | `补洞` / `最大补洞` | 补不补洞、最多补到画面的百分之几 |
| 输入 | `平滑` | 化掉锯齿的像素数，不加羽化 |
| 输入 | `边缘精修` / `导向图` | 关 / 导向滤波 / 抠像；选了后两个要接导向图 |
| 输入 | `黑场` / `白场` | 色阶，最后一步 |
| 输入（可选） | `预览` | 把结果画在节点脸上，默认开 |
| 输出 | `遮罩` | 修好的遮罩 |
| 输出 | `反相遮罩` | 取反，给处理背景的节点用 |

> 搬运自 ComfyUI-AusBoss「Mask Refine」，MIT，保留原出处。

## 遮罩裁剪 / 裁剪恢复

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_MaskCrop`）· 参考 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「GH_MaskCropV2」的用法，代码自写
> **来源**：原创（`QG_CropRestore`）· 参考 孤海工具箱 Goohaitools-comfyui（GPL-3.0）「GH_CropRestore」的用法，代码自写
<!-- QG-ORIGIN:END -->

一对配套节点，走的是「裁小的那块去处理，处理完贴回原位」：

`按遮罩取材 → 送去放大 / 重绘 → 贴回`

- **遮罩裁剪** —— 按画好的遮罩量出包围盒，四边各自留出可调的余量（相对遮罩**最短边**的倍数，1.4 就是多留 40%），再规整成 8 的倍数好进 latent。裁到画面外的部分用它自己的边缘颜色填上，而不是抹黑
- **裁剪恢复** —— 把处理过的裁剪图缩回原来的矩形，通过遮罩混回原图。**遮罩以外的像素与原件逐像素相同**，整张图其余部分一个像素都不经过缩放

尺寸有三种取法：

| 尺寸模式 | 做什么 | 什么时候用 |
|---|---|---|
| `原尺寸` | 遮罩 + 余量，向上取整到倍数 | 最常见的「裁出来正好」 |
| `正方形` | 补成最大边长的正方形 | 要喂只吃方图的分辨率档位 |
| `自定义` | 按指定宽高取景（**cover**，不是 fit） | 模型要求 1024×1024 之类 |

`自定义` 只填一边、另一边填 0 时，0 的那边按比例推出来。取景是 **cover**：先把矩形按目标比例补宽或补高，再缩到目标尺寸，所以主体**不会被压窄**，多出来的部分是填色。

### 输入 / 输出

**遮罩裁剪**

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` / `遮罩` | 要裁的画面，和要留住的范围 |
| 输入 | `尺寸模式` | 原尺寸 / 正方形 / 自定义 |
| 输入 | `自定义宽` / `自定义高` | 只在自定义下用，默认 1024 × 1024 |
| 输入 | `倍数取整` | 向上取整到它的整数倍，默认 8；1 关闭 |
| 输入 | `上扩展` / `右扩展` / `下扩展` / `左扩展` | 遮罩最短边的倍数，1.0 紧贴边缘 |
| 输入 | `遮罩补洞` | 先补上遮罩自己围住的窟窿再量尺寸 |
| 输入 | `填充方式` | 边缘取色 / 边缘拉伸 / 黑色 |
| 输出 | `接缝` | 恢复用的全部信息（原图 + 矩形 + 裁剪尺寸），接到裁剪恢复 |
| 输出 | `裁剪图像` / `裁剪遮罩` | 裁出来的一块 |

**裁剪恢复**

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `接缝` / `图像` | 裁剪的接缝 + 处理完的裁剪图（尺寸随意，会缩回去） |
| 输入 | `遮罩扩张` | 贴之前把遮罩放大几像素，4~16 能盖住重绘的接缝 |
| 输入 | `羽化` | 边在这多像素里过渡，0 是硬边 |
| 输入 | `颜色对齐` | 中位配色对齐，消掉缩放往返留下的明度漂移 |
| 输入（可选） | `裁剪遮罩` / `背景图像` | 改过的裁剪遮罩；换个背景贴 |
| 输出 | `图像` | 贴回后的整张图 |

整批（多帧）共用**一个**裁剪矩形（所有帧遮罩的并集），所以视频不会一帧一个取景地抖。

**还没画遮罩时不会报错** —— 整张图原样通过（日志里提示一句）。这一步通常是工作流还没画完，
不该为此中断整条流程。画好之后再跑就是正常裁剪。

> 自写。功能对位孤海工具箱（GPL-3.0）「遮罩裁剪V2 / 裁剪恢复」，代码重写。

## 重绘裁剪 / 重绘缝合

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_CropForInpaint`）· 参考 ComfyUI-AusBoss（MIT）「Crop For Inpaint 🆎」的用法，代码自写
> **来源**：原创（`QG_StitchInpaint`）· 参考 ComfyUI-AusBoss（MIT）「Stitch Inpaint 🆎」的用法，代码自写
<!-- QG-ORIGIN:END -->

一对留给「重绘」的节点：`重绘裁剪` 按遮罩把要画的地方裁出来，`重绘缝合` 把画完的结果贴回去。

跟 `遮罩裁剪 → 裁剪恢复` 的分工：

| | 遮罩裁剪 → 裁剪恢复 | 重绘裁剪 → 重绘缝合 |
|---|---|---|
| 用途 | 纯几何裁剪，切出来给放大、换脸、单独处理 | 重绘 / 扩图，模型要看得懂周边 |
| 上下文 | 按最短边倍数扩边 | `上下文倍数` + `额外上下文`，还能按目标面积重采样 |
| 贴回 | 硬贴，只按羽化混 | 羽化混 + 色调匹配 + 边缘光环修复 + 沿画面自身边缘渐变 |
| 数据 | 自家一对 `QGSeam` | `AUSBOSS_STITCHER`，和 AusBoss 互通 |

### 重绘裁剪

按遮罩包围盒裁出区域，四周带上下文，缩放到采样器接受的尺寸，同时输出一份**缝合数据**。

- `上下文倍数` —— 1.0 紧贴遮罩，1.2 是默认值
- `贴回羽化` —— 只羽化贴回那条边，不动采样遮罩；要改重绘范围用 `遮罩扩缩` / `遮罩羽化`
- `目标面积` / `目标宽高` —— 把裁剪图缩放到目标尺寸，`尺寸对齐` 保证能被采样器接受
- `向左 / 右 / 上 / 下扩` —— 直接长画幅，这就是它的扩图用法
- `不越界`（默认开）—— 上下文碰到画面边缘就停，模型只看到真实像素

三个输出：`裁剪图像`、`采样遮罩`、`缝合数据`。

**遮罩是空的就选整张画面**，缝合回来原样不动。核心「加载图像」没画遮罩时给的 64×64 占位算「空」不算「错」，不会把整条 prompt 拦下来。

### 重绘缝合

- `缝合数据` —— 接 `重绘裁剪`；扩图接了补边画布时，也可以接 `裁剪 + 旋转 + 补边`
- `重绘图像` —— 采样器出来的结果；尺寸被采样器改过也没关系，会先缩放回裁剪窗口
- `接缝方式` —— `经典贴回`（默认，既有工作流都是它）/ `融入画面`（扩图、斜着转更自然，沿画面自身边缘渐变交给原图）
- `色调匹配` —— 新区回来偏亮、偏暗或偏暖时往回调，需要羽化才有意义
- `边缘光环修复` —— 羽化接缝留下一圈暗边或亮边时打开，需要可选的 `pymatting`

缝合没碰到的像素**与原始画面逐位相同**，不经过任何缩放。`混合遮罩` 标出改动范围，可以接色调匹配或合成节点。

### 和 AusBoss 互通

槽类型是 `AUSBOSS_STITCHER`、数据里的 `kind` 是 `ausboss_inpaint_stitcher`，这两个字符串**故意保留原样**：两个插件都装时，任意一边的裁剪都能喂任意一边的缝合，结果逐像素一致（`tools/_check_stitch_inpaint.py` 里 52 项断言守着这条）。改名会让两边互相不认识，老工作流直接断线。

## 文本替换

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_TextReplace`）· 参考 ComfyUI_Comfyroll_CustomNodes（MIT）「CR_TextReplace」的用法，代码自写

最多三组「查找 → 替换」，一次配好一整条清洗链。

## 尺寸选择器

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_SizeSelector`）· 参考 ComfyUI_Muye（MIT）「MuyeSizeSelector」的用法，代码自写
<!-- QG-ORIGIN:END -->


选好比例，节点直接给出空 Latent 和实际宽高。

- **预设 + 自定义** —— 预设列表覆盖常见比例；也可以在 `比例` 里自己填 `16:9`、`2.39:1`、`1 1`
- **长边缩放** —— `长边` 填 0 用预设原始尺寸，填 N 就把长边缩到 N 并保持比例
- **百万像素** —— `百万像素` 填 `1.0` / `2.0` 就按面积定尺寸，形状仍由比例决定
- **潜在通道数** —— 4 给 SD1.5 / SDXL，16 给 Flux / SD3 / 视频模型（**上游写死 16，这里是可选的**）
- **帧数与对齐** —— `帧数` 大于 0 即视频模型；`对齐倍数` 把宽高贴到 8/16/32 的倍数上
- **比例不漂移** —— 比例和对齐倍数同时生效时按 `w = rx·k`、`h = ry·k` 求解，两个方向
  同时落在网格上、比例仍然精确；上游是「先改比例、再各自向上取整」，会漂（16:9 在 32 下
  曾被算成 1344×768 = 7:4）
- **自动适配模型的下采样倍数** —— 输出的 Latent 会声明「按 8 倍下采样做的」，16 倍的模型
  （Qwen Image 2.x、Flux 2 Klein）由采样器自己换算；缺了这个声明，出图会正好是设定值的两倍

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `预设尺寸` / `批次大小` | 起手尺寸与批大小 |
| 输入 | `长边` / `比例` / `帧数` / `对齐倍数` / `潜在通道数` | 尺寸微调 |
| 输入（可选） | `宽（覆盖）` / `高（覆盖）` | 接任意数值，大于 0 就优先用它 |
| 输入（可选） | `百万像素` | 0 = 不用；非 0 就按这个面积定尺寸 |
| 输出 | `Latent` / `宽` / `高` / `帧数` | 空潜在张量 + 实际使用的数值 |

> 搬运自 ComfyUI_Muye（尺寸选择器），MIT，保留原出处。

## 空 Latent 分辨率（比例 + 百万像素一步出 latent）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_EmptyLatentResolution`）· 作者自有插件 ComfyUI-EmptyLatentResolution（MIT）「EmptyLatentResolution」，合并进来
<!-- QG-ORIGIN:END -->

官方的「分辨率选择器」算宽高、官方的「空 Latent」吃宽高，中间得连两根线。这个节点把两步合成一步：
选比例、给百万像素，直接出空 Latent，同时把算好的宽高也送出去。

- **省掉两根线** —— 宽高在节点内部算完就用了，`width` / `height` 同时作为整数输出，
  下游要拿尺寸的地方不用再挂一个测量节点
- **八种比例，写的是摄影叫法** —— `1:1` / `3:2` / `2:3` / `4:3` / `3:4` / `16:9` / `9:16` / `21:9`，
  下拉里标成 Square / Portrait Photo / Widescreen 这些，带 Portrait 的是竖图
- **按面积定尺寸** —— `百万像素` 填 `1.0` / `2.0` 就按总像素算，形状仍由比例决定：
  1.0 MP 在 1:1 下约 1024×1024，2.0 MP 在 3:4 下是 1256×1672
- **对齐倍数可调** —— `对齐倍数` 默认 8（和 latent 的 8 倍下采样对齐），16 / 32 / 64 给新一代模型用；
  宽高先向倍数取整再对齐，不会出现半格
- **和官方算出来的一样** —— 尺寸算法与官方 `ResolutionSelector` 逐行一致（同样的 `sqrt` 缩放、
  同样的 multiple 取整），8 种比例 × 4 档百万像素 × 4 档倍数的 **128 组参数实测逐个相同**；
  latent 结构也与官方 `EmptyLatentImage` 一致（4 通道、同样的 `intermediate_device` /
  `intermediate_dtype`、同样带 `downscale_ratio_spacial=8`）—— 所以把原来那两个节点换成这一个，
  出图尺寸不会变
- **节点上直接看得到结果** —— 自带分辨率预览框，拖比例或百万像素时实时画出得到的形状，
  不用先跑一遍才知道算出多少

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `宽高比`（`aspect_ratio`） | 八种预设比例，决定形状 |
| 输入 | `百万像素`（`megapixels`） | 目标总像素（百万），决定大小 |
| 输入 | `批量大小`（`batch_size`） | 一次出几张空 latent |
| 输入（高级） | `对齐倍数`（`multiple`） | 宽高向这个倍数取整，默认 8 |
| 输入（可选） | `分辨率预览`（`preview`） | 预览控件，读上面三个控件，不参与提交 |
| 输出 | `Latent` / `宽` / `高` | 空潜在张量 + 最终像素宽高 |

## 图像缩放（图像 + 遮罩同步，10 个控件）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ImageScale`）· 作者自有插件 ComfyUI-QG-Multipack v0.1.0（GPL-3.0-or-later）「QG_ImageScale」，合并进来
<!-- QG-ORIGIN:END -->


图和跟着来的遮罩一起缩，**顺手把实际宽高当整数输出**，下游算尺寸的地方不用再接测量节点。

- **三种定尺寸方式** —— `按长边等比例` / `按短边等比例`（都套用「将边缩放到」的长度）/ `自定义宽高`（用上面的宽、高，填 0 表示由另一边推算）
- **六种缩放模式** —— 拉伸 / 裁剪 / 三种填充（自定颜色、边框颜色、边缘像素）/ 总像素等比例
- **五种插值** —— 双线性 / 双三次 / 区域 / 邻近-精确 / Lanczos。**遮罩与图像用同一个插值**，不是遮罩常用的邻近
- **固定方向** —— 裁剪或填充时留哪一侧：居中 / 上 / 下 / 左 / 右
- **执行条件** —— 总是执行，或只在最长边大于 / 最小边小于目标时才动
- **整除数** —— 把结果对齐到 8 / 16 / 64 这类倍数，不同模式的取整方向不同
- **至少接一个** —— 只接遮罩时图像输出黑色占位图；遮罩没接时输出全黑

🔴 **几处「看着不对」但照原样保留的行为**（为了让同一组参数能和「图像缩放V2 孤海」直接互换）：

- 按长边 / 短边等比例且整除数 ≤ 1 时，**完全忽略缩放模式** —— 裁剪和各种填充都不生效
- 填充\_边缘像素的四角保持黑色，不向外延展
- 总像素\_等比例按 `sqrt(总像素 / 原宽高比)` 起算，必要时在 ±1 里挑候选
- 「不需要缩放」分支里整除数变小时直接 crop，不重新插值

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `宽度` / `高度` | 自定义宽高模式用；填 0 由另一边推算 |
| 输入 | `缩放方法` | 按长边等比例 / 按短边等比例 / 自定义宽高 |
| 输入 | `将边缩放到` | 等比例模式的目标边长；也参与条件判断 |
| 输入 | `缩放插值` | 五种插值，图像与遮罩共用 |
| 输入 | `缩放模式` | 拉伸 / 裁剪 / 三种填充 / 总像素等比例 |
| 输入 | `固定方向` | 居中 / 上 / 下 / 左 / 右 |
| 输入 | `执行条件` | 总是 / 最长边大于时 / 最小边小于时 |
| 输入 | `填充颜色` | `#RRGGBB`，默认 `#364254`（本包没有取色器，手填） |
| 输入 | `整除数` | 0 或 1 表示不对齐 |
| 输入（可选） | `图像` / `遮罩` | 至少接一个 |
| 输出 | `图像` / `宽度` / `高度` / `遮罩` | 缩放结果 + 实际宽高 + 同步缩放后的遮罩 |

> 参数与 Goohaitools「图像缩放V2 孤海」逐项对齐，同一组数值可以直接搬过来。
>
> 这个节点**顶替**了原来的「图像缩放（像素或百分比，crop / pad / contain）」。两者接口不兼容
> （旧 6 项控件 / 3 路输出，新 10 项控件 / 4 路输出），所以换了 ID 而不是沿用 —— 老工作流打开会
> 报「节点类型不存在」，而不是把 5 个值按位置塞进 10 个控件里跑出错图。

## 图片标准化（把图塞进模型的分辨率桶）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ImageNormalize`）· 作者自有插件 ComfyUI-QG-Multipack v0.1.0（GPL-3.0-or-later）「QG_ImageNormalize」，合并进来
<!-- QG-ORIGIN:END -->


Qwen-Image、SDXL、Flux 这些模型并不是「随便什么尺寸都能吃」——它们各自有一组训练时用过的
标准尺寸（分辨率桶）。这个节点把任意尺寸的图塞进其中一个桶：**按比例挑最近的桶 → 等比缩放到
盖住它 → 居中裁掉多出来的边**。输出永远是那个桶的标准尺寸，不会拉伸变形。

- **一次选模型又选档位** —— `Qwen-Image 1K` / `2K`、`SDXL 1K`、`SD 1.5 512` / `768`、
  `Flux 1MP` / `2MP`。ComfyUI 的下拉是静态的，模型族与分辨率档位没法联动，所以合成一项
- **13 种比例** —— 1:1、4:3、3:4、5:4、4:5、3:2、2:3、16:9、9:16、21:9、9:21、2:1、1:2。
  SDXL 官方只有 9 种，5:4 / 2:1 这类会匹配到最近的邻居
- **代价是裁边，不是变形** —— 5:4 的图塞进 16:9 的桶会左右裁掉一大块。想保留完整画面请用
  「图像缩放」的填充模式
- **报出裁了多少** —— `匹配比例` 告诉你落到哪一档，`宽度` / `高度` 是实际输出尺寸，
  `基准边长` 是该档位的正方形边长（用来反推缩放倍率）

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（必填） | `图像` | 要标准化的图像，帧数不变 |
| 输入（必填） | `模型档位` | 七种模型族 + 档位组合 |
| 输入（必填） | `缩放算法` | lanczos（默认，最锐利）/ bicubic / bilinear / nearest |
| 输出 | `图像` | 裁到匹配桶之后的图 |
| 输出 | `宽度` / `高度` | 匹配到的桶尺寸 |
| 输出 | `匹配比例` | 桶的比例名，如 `16:9` |
| 输出 | `基准边长` | 该档位的 1:1 边长 |

> **与「图像缩放」不重复**：那个是自由的（缩放模式、插值、整除数、遮罩同步、填充颜色十项
> 控件都自己定），你让它多大就多大；这个的尺寸不是你决定的，是**模型档位**决定的，它只负责
> 「塞进最近的那个桶」。要出图给 Qwen-Image 用就选这个，要精确控制像素就选那个。

## 图像或 Latent 尺寸（宽 / 高 / 帧数，一个入口）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ImageOrLatentSize`）· 参考 rgthree-comfy（MIT）「Image or Latent Size」的用法，代码自写
<!-- QG-ORIGIN:END -->


接什么都行 —— 图像、遮罩、Latent，节点回 `宽` / `高` / `帧数` 三个整数。

- **Latent 自动 ×8** —— Latent 里存的是下采样之后的尺寸（`(B, 4, H/8, W/8)`），
  这里乘回去，给你真实的像素尺寸
- **`帧数` 就是 batch 维** —— 8 张图给 8，单张 `(H,W)` 遮罩给 1，空批次给 0。
  接 `EmptyLatentImage` 的 batch、算总帧数、判断「这批是不是空的」都能直接用它
- **遮罩和图像靠维度自动分** —— 2 / 3 / 4 维都认：`(B,H,W)`、`(B,1,H,W)`、`(H,W)`
  当遮罩，`(B,H,W,C)` 当图像。四维两者长得像，判据是**末维是不是通道数**
  （1 / 3 / 4），所以**高度为 1 的图也能读对** —— 这也是它比上游多出来的一条
- **非 torch 输入也认** —— numpy 数组、嵌套列表都能读形状，不会掉进「读不出来」
- **没接东西回 0 / 0 / 0** —— 不报错，方便先把线拉好再连上游
- 典型用法：接在「图像缩放」之后看实际尺寸、给「按当前尺寸算缩放比例」的分支提供
  输入、超分之前先确认原图多大、拿 `帧数` 去拼总时长

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入（可选） | `输入` | 图像 / 遮罩 / Latent 都收 |
| 输出 | `宽` / `高` | 宽高，Latent 已乘回 8 倍 |
| 输出 | `帧数` | batch 维。单张 `(H,W)` 遮罩算 1；Latent 取 samples 的第 0 维 |

> 🔴 **行为变化（2026-11-08）**：接了东西但**读不出宽高**时现在会**报错**，不再静默给
> `0 / 0`。以前接一个一维张量或字符串，这里给 0，最后在 `EmptyLatentImage` 那里炸
> 「width must be > 0」，看不出 0 是从哪来的。**没接线仍然是 0** —— 那是契约。
>
> `帧数` 这一路是本轮从自有插件 `QG_GetImageSize`（与这个节点几乎完全重叠，所以没有再
> 搬一个同类节点进来）合并的。同一组形状两边逐组比对过：4 维 108 组、3 维 27 组、2 维
> 9 组，宽 / 高 / 帧数三项全一致。五维视频 latent 的**时间维不猜**（维度顺序没有标准），
> 只报 batch。

> 搬运自 rgthree-comfy（`Image or Latent Size`），MIT，保留原出处。

## 比例与分辨率（按比例算宽高）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_RatioResolution`）· 作者自有插件 ComfyUI-QG-Multipack v0.1.0（GPL-3.0-or-later）「QG_RatioResolution」，合并进来
<!-- QG-ORIGIN:END -->


给一个比例和一个定尺寸方式，算出宽高。**它不产出 latent** —— 只算数，把结果接给任何要尺寸的地方。

- **六种定尺寸方式** —— 固定长边 / 固定短边 / 固定宽度 / 固定高度 / 总像素 / 长边范围
- **总像素与官方同口径** —— 百万像素按 1024² 算面积再开方，和 ComfyUI 自带的 Resolution Selector 一样
- **长边范围会跟随原图** —— 接一张图进来，它的长边被夹进「长边最小 ~ 长边最大」之间；没接图按 1536 兜底。最小填得比最大大，两者自动对调
- **原始比例** —— 接图就用图的宽高比，没接按 1:1
- **输出口旁有青色实时预览** —— 改任何控件，宽度 / 高度旁边立刻显示预计值；执行后回显真实结果（中间隔着别的图像节点、运行前读不到尺寸时，要等执行完才有数）
- **控件会自动显隐** —— 选「自定义宽高」就只留两个宽高框，选「总像素」只留百万像素，选「长边范围」只留最小 / 最大。用不上的项不占位置
- **倍数取整** —— 宽高各自就近取整到 N 的倍数（默认 16）。结果不足一个倍数时仍给一个倍数，不会出 0

### 输入 / 输出

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `比例` / `模式` | 13 种比例（含原始 / 自定义）+ 6 种定尺寸方式 |
| 输入 | `固定边像素` | 固定长边 / 短边 / 宽度 / 高度用的边长，默认 1024 |
| 输入 | `百万像素` | 总像素模式的面积，默认 2.0 |
| 输入 | `长边最小` / `长边最大` | 长边范围模式的夹取区间，默认 512 ~ 2048 |
| 输入 | `自定宽度` / `自定高度` | 自定义宽高模式直接用的数，默认 1024 |
| 输入 | `倍数取整` | 默认 16；0 表示取整到整数 |
| 输入（可选） | `图像` | 原始比例读它的宽高比，长边范围读它的长边 |
| 输出 | `比例` / `宽度` / `高度` | 比例字符串（原始 / 自定义给最简整数比）+ 两个整数 |

> 🔴 **和「空 Latent 分辨率」「尺寸选择器」不是一回事**：那两个节点直接产出 `LATENT`，是「生成一张空画布」的；这个节点只算数，输出的是可以接给任何 width / height 参数的整数。要开画布就在后面接一个 `Empty Latent Image`。
>
> 算法与 Goohaitools「比例与分辨率」逐项对齐，同一组参数两边结果完全相同（1248 组对照过）。

## 导出图像（JPEG / PNG / WEBP，画质就在保存这一步）

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_ExportImage`）
<!-- QG-ORIGIN:END -->


原生 `SaveImage` 只会写 PNG。社区的 JPG 保存节点大多把 `quality` 写死 90，让你在前面
串一个「压缩」节点 —— 那套**不起作用**：压缩节点交出去的是张量，保存节点会重新编码，
最终画质由保存节点说了算，前面那个旋钮只会白白毁一次图。

所以这里的画质旋钮就放在**真正编码的那一步**：

- **三种格式** —— `JPEG`（有损，最小）/ `PNG`（无损，最大）/ `WEBP`（兼顾，支持透明）
- **`质量` 只对 JPEG / WEBP 生效** —— PNG 是无损的，填了也不参与（压缩级别固定 4，
  与原生 SaveImage 同档）
- **`色度采样` 只对 JPEG 生效** —— `4:4:4` 保留全部彩色细节；`4:2:2` 省约 15% 体积、
  红橙边缘开始发软；`4:2:0` 再省一些
- **透明怎么处理** —— 合成白底 / 合成黑底 / 保留透明（PNG、WEBP 支持）。选 JPEG 时
  「保留透明」会自动退化成白底，不会糊出一圈黑边
- **文件名与原生同形** —— `ComfyUI_00001_.jpg`，五位数递增，扫描目录取最大值 +1，
  所以和原生 `SaveImage` 往同一个文件夹存也**不会互相覆盖**
- **前缀能写模板** —— `%date:yyyyMMdd%` / `%time:HHmmss%` 里可以用
  `yyyy yy MM dd HH hh mm ss`；另有 `%INDEX%`（批次内第几张）和 `%BATCH%`（总数）。
  原生那套 `%width% %height% %year% %month% %day% %hour% %minute% %second% %batch_num%`
  也认，两套可以混着写
- **能存到任意目录** —— 留空写 `output`；填 `auto 图/2026` 就是 output 下的子目录；
  也可填绝对路径、网络共享（`\\NAS\共享\图`）、环境变量（`%USERPROFILE%\Desktop\图`）或
  `~\Desktop\图`。**系统目录、盘符根目录、只写一个盘符（`D:`）会被直接拒绝**，
  相对路径也不许跳出 `output`
- **自定义目录也有预览** —— ComfyUI 的 `/view` 只服务 `output`，所以另存一份最长边
  1600 的缩略图到 `temp` 给节点显示，不为了预览再存一张全图
- **不会被缓存跳过** —— 保存节点每次都真的写盘，不会因为「输入没变」就不存

| 方向 | 名称 | 说明 |
|---|---|---|
| 输入 | `图像` | 图像批次，每张单独存一个文件 |
| 输入 | `格式` | JPEG / PNG / WEBP |
| 输入 | `质量` | 1–100，默认 90（只对 JPEG / WEBP） |
| 输入 | `色度采样` | 4:4:4 / 4:2:2 / 4:2:0（只对 JPEG） |
| 输入 | `透明处理` | 合成白底 / 合成黑底 / 保留透明 |
| 输入 | `文件名前缀` | 前缀 + 日期时间与序号模板 |
| 输入（可选） | `保存路径` | 目标目录，留空 = `output` |
| 输出 | — | 没有输出槽（终点节点） |

> 原创。只借了同类节点「画质旋钮该放在编码那一步」的结论，代码没搬。

## 采样预览

<!-- QG-ORIGIN:BEGIN -->
> **来源**：原创（`QG_StepPreview`）
<!-- QG-ORIGIN:END -->


`--preview-method` 是**启动参数**：一旦写进启动器，服务器上每个工作流都跟着它，
要改只能重启 ComfyUI。于是要么全局关掉（想瞥一眼采样过程就得重启），
要么全局开着（不想预览的那条工作流也跟着拖慢）。

这个节点把开关**按工作流**给出来：丢在画布任意位置，不用连线，只有它所在的那份工作流
会显示采样中间步骤；跑完自动复位，别人的工作流、下一次排队都不受影响。

- **节点里直接看画面** —— 采样时画面就在这个节点里长出来，不用去盯 KSampler
- **第几步一目了然** —— 底部状态栏写着 `step 7 / 20`，跑完变成「完成」
- **能随时叫停** —— 底部有 STOP。出图跑偏时不必等它跑完，中断后画面留在节点上
- **三种预览方式** —— `快速`（Latent2RGB 直接映射，不加载任何模型）/ `清晰`（TAESD 解码，接近真实画面）/ `关闭`
- **预览尺寸可调** —— 最大边长 64–2048，默认 512。远程连服务器时调到 256 能明显少传数据
- **不用连线** —— 丢在画布任意位置即可，它不在数据流里，只负责开开关
- **能从「全局已开」里关掉** —— 启动参数写了 `auto`、但这条工作流不想预览，把方式设成 `关闭` 即可。
  **关掉的是采样中间帧，不是成品图**：跑完照样会显示 `预览图像` / `保存图像` 的成品
  （成品图走 ComfyUI 的执行结果，跟采样预览没有关系）
- **三个参数收在齿轮里** —— 预览方式 / 最大边长 / 隐藏缩略图不进节点版面，
  点右下角 ⚙ 才展开，收起来时节点只有一块画面
- **缩略图只在面板里** —— 勾上「隐藏采样器缩略图」，画面就只在这个节点里出现，
  KSampler 上不再挂一张同样的小图。这是显示层的事，预览本身照旧在跑，
  **省不了服务器开销**，只是把画布腾干净

三个参数都在右下角 ⚙ 里：

| 名称 | 说明 |
|---|---|
| `预览方式` | 自动 / 快速 / 清晰 / 关闭 |
| `最大边长` | 预览图的最大像素边长，只影响预览，不影响出图 |
| `隐藏采样器缩略图` | 勾上后采样器节点上不再显示缩略图，画面只在面板里 |

跑完之后如果有 `预览图像` / `保存图像`，节点里会换成**成品图**；没有的话保留最后一帧预览
（那是 Latent2RGB 的糊图，正常）。`关闭` 这一档没有中间帧，所以只有成品图——
工作流里一个 `预览图像` / `保存图像` 都没有时，节点跑完就是空的。

**怎么生效的**：新版 ComfyUI 在读 `extra_data["preview_method"]`（`PromptExecutor.execute_async`
第一行就是 `set_preview_method(...)`，传 `None` 则恢复启动默认）。本节点在排队**之前**由
`PromptServer.add_on_prompt_handler` 改写这个字段，一个字节的后端代码都没打补丁；
下个工作流不带这个节点，字段自然为空，ComfyUI 自己就复位了。

画面则是 ComfyUI 的采样器自己逐步骤发出来的，前端把那些帧接进节点里的画布；
STOP 调的是 ComfyUI 自己的中断接口，和工具栏上那个「取消」是同一个。

老版本 ComfyUI 没有 `extra_data` 这个字段时，退化成节点执行时直接改全局设置 ——
只能影响它之后执行的采样器，精度差一点，但总比整台服务器重启强。

## Nodes 2.0（Vue 渲染）

ComfyUI 新版可以把节点渲染成 Vue 组件（设置里的「Nodes 2.0 / Vue 渲染」）。
开启后画布不再调用节点自己的 `onDrawForeground`，所以**把界面画在 canvas 上的节点会整块消失**。
本包把这类节点全部迁到了 DOM，两种渲染模式下表现一致：

- **数值 / 开关**：数值、布尔开关、运行计时
- **图像**：导出图像（含概要行与齿轮）

其余节点（各类加载器、显示任意、文本替换、加载文档、数学运算……）本来就以 DOM 卡片
或原生控件呈现，两种模式下一直在。

几个要点：

- **就地切换，不重载工作流** —— 改设置的那一刻，节点自己从旧容器搬到新外壳，位置、连线、
  选中状态、正在编辑的文字全部保留；撤销栈也不会被清掉。
- **双击进入编辑**（标签 / 便签类）—— Vue 模式下单击被用来拖节点，所以编辑改成双击，
  阈值放宽到 750ms，手慢一点也算。
- **不出双影** —— Vue 模式下 `draw()` 直接短路，画布上不重复画一遍。
- **尺寸按外壳换算** —— Vue 会额外加 30px 标题栏和最小宽度，插件按它算节点尺寸，
  切换瞬间节点不会突然变宽变高。

切 ComfyUI 自己的界面语言就行：**中文界面显示中文，英文界面显示英文**，不用装汉化插件。

- 后端代码里写的是英文（节点标题、输入输出名、提示文字、下拉选项的值），中文来自插件
  自带的 `locales/zh/nodeDefs.json`，ComfyUI 语言切到中文时自动叠上去。两边的对应关系
  由 `tools/verify_bilingual.py` 双向体检：英文侧不许残留中文，中文侧不许漏条、不许
  只是把英文抄一遍。
- 覆盖范围：节点标题、输入 / 输出名、每个输入的提示、右侧 `?` 说明卡、下拉选项的显示名。
  下拉是**逐个登记**的：本包 23 个带下拉的节点、40 个下拉输入、347 条选项值全部有中文名
  （含翻译节点的 106 个语言码，`af` 显示成「南非荷兰语」）。文件名、模型名这类列表和
  `JPEG` / `PNG` 这种中英同形的值是刻意不翻的。
- 下拉选项的**值是英文**（`on-white` 这类），中文界面显示的是对应的中文译名（`合成白底`）。
  存进工作流的是英文值，所以同一份工作流在两种界面下都能跑，也不会因为换界面而失效。
- **老工作流不用改**：v0.9.4 之前的存档存的是中文选项值，打开时前端会就地换成英文值；
  绕过前端（API 直连、脚本批量跑）也照样能执行，节点内部还会再兜一次。
- 装了 [ComfyUI-Chinese-Translation](https://github.com/DrippyForever/ComfyUI-Chinese-Translation)
  这类汉化插件时，本包还额外提供前端面板文案的汉化（按钮、菜单、状态提示）。
- **节点菜单里的分类名**后端写英文（`QG-tools/Loaders`、`QG-tools/Mask`），中文界面的
  「加载器」「遮罩」来自插件自带的 `locales/zh/main.json` 里的 `nodeCategories`
  —— 这是 ComfyUI 自己的分类翻译通道，跟节点标题一样，**不用装汉化插件**。
- 节点标题不带 `QG` 前缀（分类仍在 `QG-tools` 下），所以标题栏干净、搜索框里也不会被一串同名前缀刷屏。

> 本文档里的节点名与选项名（`添加水印` / `合成白底` / `采用比例` 这类）都是
> **中文界面上看到的名称**；英文界面下它们是等价的英文值，选项值形如 `on-white`、
> `from-preset`（小写 + 短横线）。两种写法指的是同一个东西，老工作流里的中文值
> 会自动迁移，不用手改。

## 中英文搜索

节点标题跟着界面语言走（中文界面 `添加水印`、英文界面 `Add Watermark`），
**中英文都能搜到**：中文靠语言包里的译名，英文靠标题本身。除此之外每个节点还登记了一组
口语叫法（`web/shared/node_aliases.mjs`），页面加载时写进节点定义的 `search_aliases`，
ComfyUI 的搜索框会把它们和标题一起做模糊匹配。

> 中文名里带空格的节点（比如 `空 Latent 分辨率`）另登记了**无空格写法**：
> 敲 `空latent`、`空Latent`、`空latent分辨率` 都能搜到。
> 只按字面子串比的话，`空 latent` 命中而 `空latent` 不命中，所以这层变体是必要的。

| 想找 | 可以搜 |
|---|---|
| 图像对比 | `compare` / `image compare` / `ab compare` / `diff` / `before after` |
| 添加水印 | `watermark` / `logo` / `stamp` |
| 图像裁剪 + 旋转 + 补边 | `crop` / `rotate` / `pad` / `outpaint` |
| 模型加载器 | `triple loader` / `model loader` / `checkpoint` / `unet clip vae` |
| 尺寸选择器 | `size selector` / `aspect ratio` / `resolution` |
| 空 Latent 分辨率 | `空latent` / `空 latent` / `empty latent` / `megapixel` / `百万像素` |
| 遮罩上色 / 拼接 | `mask colorize` / `mask concat` / `merge masks` |

想加词就改 `web/shared/node_aliases.mjs` 里对应节点那一行，刷新页面即可。

**命中别名的节点会往前提一点，但最多 2 个。** 这不是多余的设计：搜索框只取前 64 条，
而 `text` 这类词能命中 480 多个节点，QG 文本原本排第 159 名——等于搜不到。所以扩展会把
「别名里正好有这个词」的 QG 节点提到前面，最多提 2 个，其余保持原位。

搜 `image` 这种上位词时，登记了该词的 QG 图像类节点会被提到前面（最多 2 个）；
搜 `text` 时是 `QG 文本`、`QG 文本按分隔符分割` 排前两位。不想看到这个行为的话，
把 `web/shared/node_aliases.mjs` 末尾那几个上位词（`image` / `mask` / `size` / `model` /
`document` / `workflow` / `text`）删掉即可，节点自己的英文名还会保留。

## 生效与排障

1. 首次安装要**完整重启 ComfyUI**（不是刷新页面）。
2. 之后前端有更新时，浏览器要 `Ctrl+Shift+R` 强刷 —— ComfyUI 只在页面加载时读一次扩展列表。
   （本插件的前端子模块都带版本串，正常情况下普通 F5 也能拿到新代码。）
3. 后端共 16 条路由（LoRA 6 条 + 文档 3 条 + Google 翻译 1 条 + 图像面板的视频预览 4 条 +
   图像对比保存 1 条 + 版本探针 1 条），可用这条命令快速自检：

   ```bash
   curl http://127.0.0.1:8188/qg/pack_version
   curl http://127.0.0.1:8188/qg/lora/list
   ```

4. 拖动时看不到橙色对齐参考线？先确认没开网格吸附。两者改的都是拖动落点（一个取整到网格、
   一个对齐到其他节点），同时开会互相覆盖，所以参考线默认**主动让位** —— 而且不报错、不提示，
   看上去就像功能坏了。控制台跑这一行，返回 `true` 就是被接管了：

   ```js
   LiteGraph.alwaysSnapToGrid
   ```

   这个值由 ComfyUI-Custom-Scripts（pysssss）的设置项「🐍 Always snap to grid」控制。
   两种处理方式，按需要选一个：

   - **想保留网格吸附、也要看到参考线**：打开本插件的设置
     「网格吸附开启时也显示参考线（QG）」（`QG-tools › Canvas › Snap into line`）。
     这个模式下只画线、不改落点 —— 网格要求位置必须是 10 px 的整数倍，
     节点边缘对齐多半落不到网格上，强行写入会在松开鼠标时被网格拽回去。
   - **想要参考线的吸附效果**：关掉网格吸附。立刻生效，不用刷新页面：

     ```js
     app.ui.settings.setSettingValue("pysssss.SnapToGrid", false)
     ```

   另外按住 Shift 拖动会临时关闭参考线吸附。
